# Arcnix

Rust + Glory + Sapid 桌面服务器管理工作台。通过 SSH 管理多台服务器，提供文件管理、系统软件、运维操作、资源概览、系统日志和 Terminal 六个模块。Windows 桌面为当前验收平台；资源页提供连接期间的实时数值和会话趋势。

界面默认使用英语，可从左侧底部 **Settings** 切换为简体中文。站点名、分组名、文件路径和远程日志正文保留原文。

## 客户端代码目录

`crates/arcnix/src/main.rs` 负责启动、应用状态和事件分发。功能实现按职责放在子目录。桌面和设置在 `desktop/`，文件浏览和传输在 `files/`，Text Editor 和 Code 在 `editor/`，Player 和浏览器在 `media/`。其余目录分别负责终端、监控、自动化、维护、软件管理、应用导航、公共组件和后台请求。

`crates/arcnix-core/src/` 按连接、配置、桌面、文件、可观测性、自动化、维护和软件分组。客户端和 core 都用 `software/` 组织软件管理。客户端负责 App Center、Docker 和安装界面，core 负责软件源、包管理器、安装计划和远程操作。嵌入的 Shell 和 Python 程序与调用它们的功能在一起。公开模块通过 `lib.rs` 导出，客户端和集成测试继续使用原有模块路径。

图标源文件为 [`arcnix.svg`](../crates/arcnix/assets/arcnix.svg)，画布为 **512×512**，背景完全透明。四条单层服务器分别倾斜 ±45° 围成菱形，连接中央汇聚节点，表达多台服务器的统一管理。导航栏随主题使用同源的 `arcnix-dark.svg`／`arcnix-light.svg`，Windows 程序文件、窗口与任务栏使用通用蓝绿色版本的多尺寸 ICO。

## 页面导航

最左侧为固定图标导航栏：Logo 暂时仅作标识，点击不执行操作；**Servers** 打开服务器列表，其下为全局 **Scripts**、**Tasks**、**Backups**、**Diagnostics** 和 **Configurations**，底部提供 **Settings**。应用默认进入服务器页，左侧第二列随当前页面显示服务器列表或设置分类，右侧显示具体内容。

- Servers 未选择服务器且已有配置时显示本地记录总览，空配置保留添加提示；侧栏也可随时打开总览。选择服务器后，首个浏览器式标签固定为 **Home**，显示服务器详情及 **Desktop**、**Transfer files** 两个入口。点击入口按首次打开顺序向右新增标签，重复点击切换到已有标签，首次访问时进行 SSH 认证。三个标签共享当前服务器连接；切换服务器时重置标签。
- **Desktop** 使用壁纸、应用图标、底部 Dock 和应用窗口组织 Terminal、Resources、Software、Operations、System logs，文件管理独立位于 **Transfer files**。窗口可最小化、最大化和关闭；Dock 的圆点表示已打开应用。切换标签或关闭 Desktop 标签保留终端会话，重新打开可继续；关闭 Terminal 应用会关闭它的全部 PTY。资源采样只在资源窗口前台显示时进行，Home、文件传输及最小化后停止新请求。断开 SSH 后保留标签并显示重新连接入口。
- 主菜单不提供通知按钮；操作提示中的“查看操作日志”仍可查看本次会话最近 100 条记录，记录不跨重启保存。
- 设置页左侧提供 General、Connection、Files、Transfers、Monitoring、Logging 和 About。分类标题只在页面顶部显示，内部按具体用途分组；切换全局页面保留当前 SSH 连接及终端会话，资源自动采样仅在对应服务器页面可见时进行。

语言切换通过文本绑定更新现有界面，不按语言条件重新挂载整个应用。导航栏及按钮身份保持有效，紧接语言按钮的导航点击仍可被正常分发；设置保存成功后先更新本地化状态，再发布配置变更，使依赖配置的文字读取新语言。已销毁页面或关闭弹窗的过期事件仍由正常身份校验拒绝，不重新投递或改写为新节点。

Servers 侧栏按文件树组织：Group 是可独立展开、折叠的文件夹，组内服务器作为子项，未分组服务器直接显示在根目录。顶部的“+”在当前组中新建服务器，文件夹图标新建 Group，“…”提供根目录新建、导入和全部展开／折叠操作。搜索按组名、服务器名称、地址、用户名或分类标签匹配，并临时展开匹配组；清空搜索后恢复原来的折叠状态。

悬停或聚焦 Group、服务器时，右侧显示“…”按钮。右键 Group、服务器或树内空白处会调用同一套菜单，菜单定位在鼠标旁并自动避开窗口边缘。Shift+F10 打开键盘菜单，上下方向键移动菜单焦点，Escape 关闭；树内上下键移动焦点，左右键展开／折叠分组。菜单将两种操作分开：**Dissolve group (keep servers)**／解散分组保留全部服务器并移到根目录；**Delete group & servers**／删除分组及服务器会列出受影响服务器，确认后删除其本地配置，不操作远程主机和文件。两种操作均保留确认对话框。

Group 标题行支持鼠标拖动排序，蓝色插入线标明放置位置；顺序会写入配置并在重启后恢复。搜索期间暂时禁用排序，清空搜索即可继续拖动。展开箭头、文件夹与服务器图标均使用 SVG，统一居中并放大显示。

## 启动

源码构建需要 Rust 1.99+、Windows MSVC 构建工具、原生 Windows Perl（如 Strawberry Perl）和 NASM；运行界面需要 Microsoft Edge WebView2 Runtime。

SSH 使用源码编译并静态链接的 OpenSSL，支持 OpenSSH Ed25519 私钥（包括口令加密的私钥）及 RSA 私钥。运行应用不需要安装 OpenSSL、Perl、NASM，也不调用系统 `ssh.exe`／`sftp.exe`。首次构建会编译 OpenSSL，因此耗时较长。

升级后仍使用已有的主机信任记录。即使默认协商的主机密钥类型改变，也会先重新协商并核对原来的指纹；所有密钥都不匹配时，在发送认证信息前拒绝连接。

确保 `perl` 和 `nasm` 可从构建终端调用；便携版 Perl 也可以通过 `OPENSSL_SRC_PERL` 指定其 `perl.exe` 完整路径。Git for Windows 自带的 Perl 不适用于这里的 MSVC OpenSSL 构建。不要设置 `OPENSSL_NO_VENDOR` 或 `LIBSSH2_SYS_USE_PKG_CONFIG` 来改用系统库；构建后的程序应检查导入表没有 `libssl`／`libcrypto` DLL 依赖。

```powershell
cargo run --locked -p arcnix --bin arcnix
```

使用独立配置文件：

```powershell
cargo run --locked -p arcnix --bin arcnix -- --config ./my-config.json
```

界面和状态逻辑由 Rust 编写，Glory Wry 使用系统 WebView 作为桌面渲染宿主；无需 Node、前端打包、Web 服务器或远程 Agent。使用发布的 Glory `0.7.0` 和 Sapid `0.7.1`，不依赖机器上的其他源码仓库。

## 使用

1. 点击侧栏“新建服务器”，在模态对话框填写地址、端口、用户名，明确选择认证方式和分组。每个站点悬停时出现“…”菜单，编辑／删除针对该站点，删除前会显示确认。分组操作也在对应条目的菜单中；“新建分组”和“导入 SSH 配置”各自打开独立对话框。
2. 在 Servers 中选择左侧服务器后，点击详情卡片的 Desktop／Transfer files 或右上角 Desktop，在连接对话框中输入密码或私钥口令。私钥认证会先在本机检查私钥文件：可识别为未加密的 OpenSSH、PEM 或 PKCS#8 私钥直接连接，不再弹出口令对话框；已加密、无法读取、不是普通文件或无法识别的私钥仍显示对话框。未弹出对话框的连接失败时，若没有其他对话框或进行中的文件任务，会重新打开对话框并显示失败原因；否则只显示错误提示。断开后切换已打开的标签不会自动连接：使用未加密私钥的服务器只显示重新连接页，其他服务器仍弹出连接对话框。检查读取不超过 64 KiB 的文件内容，只判断 PEM 标记、PEM 头和 OpenSSH 文件头中的加密算法名，不解码、解析或解密私钥内容，读取后即从内存清除。运行 `python tools/connect_prompt_smoke.py` 可用隔离桌面和回环 SSH 验证未加密私钥、密码、加密私钥及失败重试四种情况。右上角统一显示当前服务器、SSH 状态和连接／取消／断开操作，所有模块共享；服务器“…”菜单也保留入口。没有站点时可从服务器列表添加。第一次连接先通过可信渠道核对 SSH 指纹，再选择保存信任或仅本次信任。已保存主机的指纹变化会拒绝认证。 连接对话框的“在这台电脑上记住”默认关闭。勾选后，SSH 登录成功且主机指纹已保存时，客户端将登录密码或私钥口令写入 macOS 钥匙串、Windows 凭据管理器或 Linux Secret Service。系统凭据独立于配置、配置备份和客户端日志。下次连接仍须匹配已保存的主机指纹。服务器拒绝凭据时，客户端删除对应条目并提示重新输入。也可通过服务器“…”菜单手动忘记凭据。删除服务器、修改登录参数或恢复不匹配的配置时会清理对应条目。
3. 文件列表单击只选中当前项，Ctrl 单击增减选择，Shift 单击按当前排序选择范围，支持 Ctrl+A、Ctrl+空格、Shift+方向键。双击或 Enter 进入文件夹；详细列表中的 `›`／`⌄` 按需展开、收起子目录。路径栏按目录分段，点击任意一段可直接跳转；编辑图标或 Ctrl+L 输入完整路径，Enter 跳转、Escape 取消，复制图标将当前完整路径写入系统剪贴板。点击列标题排序，“筛选”按名称筛选。文件传输递归包含空目录，不跟随符号链接。
4. 各文件栏的“…”菜单和右键菜单可在当前目录新建文件或文件夹。新项目立即创建，遇到重名自动追加编号，并选中名称供就地编辑。按 Enter 或移出焦点提交，按 Esc 保留默认名称。对已有项目使用“重命名”时，仍在对话框中输入新名称。
5. 底部在“传输／操作日志”标签间切换，可收起。传输队列支持进度、取消、重试、批量重试和状态筛选。暂停会阻止后续任务开始，当前任务继续运行。服务器资源统一在顶部“资源概览”查看。
6. 拖动文件双栏之间的细分隔条调整宽度，松开后保存到当前服务器的本地配置；不同服务器使用各自比例，重启后恢复。窗口变窄时临时保证最小栏宽，不修改保存的比例。分隔条可通过 Tab 聚焦，上／下方向键调整，Home 恢复均分。

新建／编辑站点保存后，侧栏自动展开其所属分组并清空搜索，保证该站点可见；从某个分组中新建时默认继承该组。创建其他站点不会中断已有的 SSH 会话。

每个文件栏右上角可独立切换 **Detailed list / Icon grid**，当前工作会话中切换目录会保留展示模式。两种模式共用选择、双击、上传下载操作；详细列表显示目录层级，图标模式平铺当前目录。底部显示选中项的名称、类型、文件大小（含精确字节数）、修改时间与时区、完整路径；远程项同时显示可用的权限位。多选时汇总选中项数量与文件大小，不递归扫描文件夹大小。

在两栏之间拖动文件或文件夹即可上传／下载，松开后保存到对侧当前目录，目标栏会高亮并显示提示。拖动已选项传输整组选择，拖动未选项仅传输该项；选中文件夹和其子项时只传输一次目录树。两种展示模式均支持，沿用队列、递归目录和同名冲突处理。符号链接、同栏放置和取消拖动不产生传输；拖动期间切换目录、刷新或更换连接会使原拖动失效。运行 `python tools/file_drag_drop_smoke.py` 可用隔离桌面和回环 SFTP 验证。

## 应用设置与本地文件浏览

左侧底部 **Settings** 打开独立设置页：

- **General / Language**：英语／简体中文，实时切换。
- **General / Theme**：Follow system（跟随系统，默认）／Dark／Light，实时应用。跟随系统时，系统深浅主题变化会自动更新界面、图标及终端配色；已有配置中明确保存的 Dark／Light 选择继续保留。
- **Files / Hidden files**：统一切换所有文件夹中的隐藏项，包括点号开头的文件及文件夹，以及 Windows 本机带有隐藏属性的项目。
- **Monitoring / Resource refresh interval**：3／5／10／30 秒，仅在资源页打开时自动采集。
- **Files / File sizes、Dates and times** 默认以十进制 KB / MB 显示文件大小，保留 1 位小数。可切换二进制 KiB / MiB、选择 0 至 2 位小数或启用千位分隔。文件与传输统计共用这些设置。日期可选择相对时间、ISO 格式或系统格式，以及当地时间或 UTC。
- **Connection**：连接超时与 SSH 保活，支持站点覆盖，下次连接生效；连接中断不会自动重放命令或文件修改。
- **Transfers**：上传／下载分别配置询问、覆盖或跳过；文件操作菜单的 **Transfer defaults** 可以按服务器覆盖或恢复继承。
- **Logging / Operation log、Log files**：操作日志的时间戳／导出与文件持久化分开。默认关闭写文件，开启后才显示目录、容量和轮转数量，默认目录位于配置旁的 `logs`；空错误不渲染，真实 I/O 错误仍显示。队列拥塞时提示丢弃记录，不能充当完整审计日志。
- **About / Application、Updates**：当前程序版本、稳定版检查、后台下载与空闲自动安装；正式版默认开启，开发版保留手动检查。更新通知的入口也跳转此页，仅在相应状态显示下载或重启操作。见[更新通道](releasing.md#desktop-update-channel)。

设置自动保存在当前本地配置中，重新启动后恢复；每台服务器的文件栏比例和已记忆的传输冲突选择仍独立保存。

选择私钥认证后，**Private key file** 旁的 **Browse…** 打开 Windows 原生文件选择窗口。支持无扩展名和中文路径，默认定位到当前路径所在文件夹（或本机 `.ssh` 目录），取消时保留原值。选择器只回填路径，不读取私钥内容，仍允许手动输入。原生对话框使用 [Windows Common Item Dialog](https://learn.microsoft.com/en-us/windows/win32/shell/common-file-dialog)。

## 文件冲突

文件管理底部的 **Transfers** 队列显示每项上传／下载的进度条、百分比、已处理／总大小、实时速度、耗时及预计剩余时间。速度采用最近约 3 秒的实际文件内容传输量计算（B/s、KiB/s、MiB/s），不包含 SSH/SFTP 协议开销，也不等同于服务器网卡总流量；等待用户处理冲突时暂停计速，持续无数据时速度回落为零。速度尚未稳定或正在扫描目录时，剩余时间显示 `—`。

每项传输左侧的箭头可展开完整文件清单，显示子目录中的相对路径、逐文件大小、百分比和等待／传输／冲突／完成／跳过／取消／失败状态。文件夹扫描完毕后建立清单，空目录仍正常创建；折叠时不渲染子文件行。上传和下载共用并发额度，默认最多同时处理 5 个文件，单个文件夹内部也会并行传输。**Settings → Transfers → Concurrent transfers** 可设为 1–16，保存后立即调整后续文件的启动额度；调低不打断已启动文件。各工作线程使用独立且校验主机指纹的 SSH/SFTP 连接，凭据仅在当前连接的内存中保留。相互重叠的传输根目录会依次执行，同一目标文件不会被并发写入。多个冲突依次显示，批次／连接规则也适用于已经排队等待的冲突。`python tools/transfer_concurrency_smoke.py` 验证实际并行进度、上限、设置持久化、冲突、取消及重试。

目录中的跳过项计入处理进度，但不计入实际传输量；队列另行显示实际传输量，结束后保留平均速度和耗时。耗时包含等待时间，平均速度排除等待冲突处理的时间。零字节文件正常完成后显示 100%，文件内容复制完成但仍在发布／落盘时显示“正在完成传输”，成功确认后才到 100%。取消或失败保留当前进度，重试使用新的统计，不提供断点续传。

上传和下载遇到同名普通文件时，默认询问，显示源文件与已有目标的路径、大小、修改时间，弹窗默认选择跳过。可以明确选择覆盖，并指定仅此文件、本次批量传输、当前连接或以后连接此服务器；上传／下载规则分别记忆。优先级为批次／连接、服务器、全局默认；服务器明确选择 Ask 时不再继承全局覆盖或跳过。服务器“…”菜单中的“重置文件冲突选择”恢复继承全局默认。

同名目录会安全合并，并逐个处理内部文件冲突；文件／目录类型冲突和符号链接会拒绝。取消或失败保留已完成文件。覆盖先写同目录临时文件，完成后替换，复制失败／取消不会先删除已有目标。远程覆盖保留已有权限位；SFTP v3 无法直接替换时使用经过路径转义和类型检查的 Linux `mv -fT`，服务器不支持时保留原目标并报告错误。下载在 Windows 使用原子文件替换。当前不提供自动重命名、大小／时间条件覆盖或续传。

默认配置存放在当前用户应用配置目录，可通过 `--config` 指定独立文件。配置保存站点、分组、主机指纹、私钥路径、上次本地目录，以及按服务器隔离的分栏比例和明确记忆的冲突规则，不保存密码、私钥口令或 sudo 密码。修改站点的地址、端口或用户名会清除原冲突规则。配置损坏时保留原文件并禁止覆盖。删除分组后，原有站点回到未分组。

Windows 默认配置路径为 `%APPDATA%\arcnix\Arcnix\config\config.json`。配置格式保持版本 1，已有配置文件可以复制到该位置，或通过 `arcnix --config <path>` 直接使用。

## 远程文本编辑

远程普通文件的右键菜单提供 **Edit file**，双击文件也可打开编辑器。支持不超过 1 MiB 的 UTF-8 文本，保留 BOM 和一致的 LF／CRLF；二进制、符号链接、混合换行与旧编码会明确拒绝。Ctrl／Cmd+S 保存，关闭有修改的草稿时确认放弃，读取／保存可取消。草稿不写配置、临时本地文件或日志。

保存前及发布前重新读取并比对 SHA-256 和元数据，检测大小／修改时间不变的外部修改。上传同目录临时文件并保留模式与属主，失败时保留原文件。此处是乐观冲突检测，SFTP 不提供跨所有外部进程的原子比较交换；多客户端同时写同一文件仍需协调。

站点的 **Files** 页设置默认本地／远程目录，可关闭记忆或清除已记忆位置；切换服务器恢复各自位置，修改地址／端口／用户时清除旧端点的记忆位置。

## Terminal

连接服务器后打开 **Desktop → Terminal**，自动打开交互式 SSH 终端。支持 ANSI 颜色、UTF-8、键盘输入、Ctrl+C、窗口大小同步和最近 5000 行滚动历史；切换页面、语言或返回文件管理会保留当前终端会话与显示内容。工具栏提供复制选中文字、粘贴、清空显示、重新启动和关闭终端的图标按钮。

远程文件的右键菜单提供 **Terminal here／在此处打开终端**：文件夹进入其自身目录，文件进入父目录，空白处进入当前目录；多选时禁用。入口会新开终端标签，保留原终端的会话、正在运行的程序及显示内容。最多保留 32 个标签，标签上的关闭按钮仅关闭该会话，工具栏重启仅重启当前标签并保留其起始目录。起始目录通过 SSH 会话启动命令按字面值传递，支持空格、中文、引号等字符；控制字符及非绝对路径不接受，目录不存在时显示退出错误，不回退到主目录。

Terminal 标签栏右侧的“＋”直接新建标签。终端区域右键打开应用菜单，提供复制、粘贴、全选、清空显示、新建、重命名和关闭标签，并分列显示快捷键；在标签上右键时，重命名和关闭操作指向该标签。菜单适配深浅主题并避开窗口边缘，Shift+F10／菜单键打开，方向键及 Home／End 导航，Escape 关闭并恢复焦点。复制使用打开菜单时的选区，粘贴不额外发送 Enter。Ctrl+Shift+T 新建，Ctrl+Shift+W 关闭当前标签，Ctrl+Tab／Ctrl+Shift+Tab 切换，Ctrl+Shift+A 全选，Ctrl+Shift+L 清空显示；Ctrl+C 保持“有选区则复制，否则中断”，Ctrl+L／Ctrl+R 保留远程终端行为。自定义标签名仅保存在当前会话内，重启该标签保留名称，断开服务器清除。`python tools/terminal_context_smoke.py` 验证右键菜单、剪贴板、多标签和快捷键。

Ctrl+C 在有选中文字时复制，否则向远程程序发送中断；Ctrl+Shift+C 复制，Ctrl+Shift+V 粘贴。清空仅清除当前显示；关闭终端不影响文件管理与全局 SSH 连接，断开服务器会同时关闭终端并清理显示。

终端通过内置 SSH 库申请 `xterm-256color` PTY，复用当前连接的认证信息与已核对的主机指纹建立独立传输连接，因此不会被文件上传下载阻塞。认证信息仅保留在当前连接的进程内存中，断开后清理，不写入配置；终端输入输出不写入应用操作日志。远程 OSC 52 剪贴板写入及链接激活已禁用。

界面状态、连接和交互桥接由 Rust 管理，终端字符渲染使用随程序本地打包的 xterm.js，不需要 Node、网络 CDN 或系统 SSH 客户端。第三方版本、来源、校验值与 MIT 许可证位于 `crates/arcnix/assets/vendor`。每个终端使用独立传输连接，新标签连接时保持其他会话响应；断开服务器清理全部标签。`python tools/terminal_here_smoke.py` 使用隔离桌面及回环 SSH 验证菜单、目录、路径字面值、会话保留及断开清理。全屏程序在真实 Linux 主机上的兼容性仍需实际环境验证。

## 系统软件

1. 连接服务器，切换“系统软件”；应用识别发行版、包管理器和管理员权限，并读取已安装软件。
2. 输入软件包名搜索，点击目标包的“安装…”打开统一服务器任务表单，预选当前服务器，也可增加其他目标。逐机预检查并审核 APT 模拟结果和现有包状态后，再提交就绪目标。
3. root 会话直接执行；其他账户通过 sudo 提权。管理员密码留空时使用 `sudo -n`，需要密码时通过本次 SSH 命令的 stdin 传递，不进入命令字符串或配置；输出中的原样凭据会被过滤。
4. “更新软件源索引”对应 `apt-get update`，同样需要确认；不会执行系统整体升级。
5. 任务输出实时显示，结束后显示退出码并刷新软件包状态。执行期间锁定当前服务器与断开入口，已有文件传输先完成，后续文件传输等待系统任务结束。

软件只读管理通过 SSH，服务器未启用 SFTP 时仍可使用。包管理写操作目前支持 Debian／Ubuntu APT；DNF、YUM、APK、Pacman 仅识别并报告支持状态。安装与索引更新交给统一 systemd 服务器任务，已确认接收后允许关闭应用及 SSH，重新连接查询原任务。暂不提供卸载、整机升级或安装自动回滚；提交结果未知时先核验，不自动重试。安装核验还要求已识别的系统版本、原生 dpkg 架构及服务器基础检查工具。

搜索最多展示 200 项，已安装列表最多展示 1000 项。软件命令采用类型化操作生成，不接受任意 shell 输入；安装先验证精确包名和模拟结果，使用 `--no-remove` 拒绝涉及移除现有包的方案。参见 [APT 操作与产品规划](server-workbench.md)。

文件传输使用 SFTP，复用同一条 SSH 连接，认证后自动打开 SFTP 子系统，不需要单独连接。文件区显示 SFTP 的可用状态；服务器未启用或账号不可访问 SFTP 时，右上角仍显示 SSH 已连接，其他 SSH 模块继续可用。当前不支持 FTP／FTPS 独立连接。

## 资源概览与系统日志

- 资源概览通过 SSH 读取 Linux `/proc` 和 `df`，显示 CPU 使用率、核心数、内存与交换空间、负载、运行时间、分区容量及网卡收发速率／累计流量，不需要远程 Agent。
- CPU 和网络速率根据两次远程采样差值计算；第一次采样显示等待，无法读取的指标显示不可用及原因。仅在资源页面自动采集，默认约 3 秒一次；安装任务期间暂停自动采集。
- 端口面板读取当前网络命名空间内 TCP 监听和 UDP 绑定端口（IPv4／IPv6），列出地址、PID、UID、程序名称、可执行路径及 systemd 单元。首次进入自动读取，之后手动刷新；本地搜索不发远程命令。扫描上限、不可读进程和旧快照均明确标记，可选择使用 sudo 查询完整的进程信息。
- 每个可核实的占用进程可打开“强制结束”确认框。执行 SIGKILL 前重新校验启动标识、网络命名空间、PID 开始时间和 socket 描述符，再通过 pidfd 发送信号；身份变化或缺少 pidfd 支持会拒绝执行。结束针对整个进程，服务管理器可能重新启动它。连接变化会取消待处理请求并清理快照与凭据。验证入口为 `python tools/resource_ports_smoke.py` 和真实 Linux 的 `python3 tools/resource_ports_linux_check.py`。
- 系统日志支持 journalctl，以及当前账户可读的 syslog、messages、auth.log、kern.log 和 APT history.log。自动发现可用来源，提供服务单元、时间范围、级别筛选和本地关键词筛选；文件来源只提供文本筛选。消息按终端 SGR 序列显示颜色和样式，规则与 Docker 日志相同；每条记录从默认样式开始，颜色不延续到下一条，关键词筛选匹配显示出的文字。
- 日志使用有界快照，可手动刷新或开启自动刷新。权限不足时显示原因，不自动提权；没有 SFTP 仍可读取资源和日志。当前不提供持续 `journalctl -f`、历史翻页或日志写入，服务控制在运维操作模块中提供。

采样与日志命令依据 [Linux proc 文档](https://www.kernel.org/doc/html/latest/filesystems/proc.html) 和 [journalctl 官方手册](https://www.freedesktop.org/software/systemd/man/latest/journalctl.html)。

## pgAdmin

macOS 的 pgAdmin 窗口运行 pgAdmin 的桌面模式后端。后端随 Arcnix 管理的组件下载：便携 Python 加上官方 pgAdmin 发布包，由 [arcnix-org/pgadmin4](https://github.com/arcnix-org/pgadmin4) 的 `arcnix-build` 分支构建并发布。`crates/arcnix-core/src/software/pgadmin.rs` 固定当前版本组件的 URL、大小和 SHA-256，升级成功后删除旧版本。每台服务器的每个数据库使用独立的数据目录。后端只监听本机回环地址，要求每次启动生成的密钥，经固定目标的 SSH 转发连接 PostgreSQL。窗口内的 WebView 只能加载该后端，复用 Code 窗口的裁切层，下载保存到「下载」。

`cargo test -p arcnix-core --test pgadmin_integration -- --ignored --nocapture` 使用真实组件、回环 SSH 和 PostgreSQL，需设置 `ARCNIX_TEST_PGADMIN_PACKAGE`、`ARCNIX_TEST_SSH_PORT`、`ARCNIX_TEST_SSH_USER`、`ARCNIX_TEST_SSH_KEY` 和 `ARCNIX_TEST_POSTGRES_PORT`。调试构建可用 `ARCNIX_PGADMIN_PACKAGE` 指定本地组件包。

## 第一版边界

- 可保存多台服务器；一个窗口同一时间连接一台服务器，传输串行排队。切换服务器会取消当前传输和排队任务。
- 支持普通文件和目录多选上传／下载；递归预扫描最多 64 层、100,000 项。符号链接／特殊文件会导致整棵目录在预扫描时失败，不会静默跳过。符号链接传输、拖放、续传、同步、远程编辑和交互式终端尚未实现。
- 文件名需要有效 Unicode；由于 Windows SSH 库的路径转换，远程包含反斜杠的路径会明确拒绝。
- 新文件下载通过同目录临时文件和硬链接发布，目标文件系统需支持硬链接（例如 NTFS）；不支持时会失败并保留已有目标。覆盖下载在 Windows 使用替换重命名。新文件上传依赖服务器遵守 SFTP 禁止覆盖重命名语义；已有文件的覆盖另有上述安全发布流程。
- 私钥算法和文件格式以 libssh2 的平台支持为准；已验证 Windows 上未加密 RSA PEM 私钥。口令入口已实现，其他密钥格式尚未逐一验证。
- Windows、macOS 和 Linux 的本地目录重命名均使用禁止覆盖目标的系统调用。

## 界面回归

Docker 适配在连接后按需检测 CLI，在桌面／Dock 动态添加入口；桌面齿轮内可重新检测。通过远程 Docker CLI 的显式本机 Unix socket 查询，优先当前用户的 rootless socket，忽略远端 Docker context／host 环境覆盖，不自动 sudo；系统套接字权限不足时提示将 SSH 账号加入 docker 组（等同 root 权限）并重新连接。容器、卷各限制 1000 项，总响应最多 2 MiB，每次 CLI 以 `timeout` 限时 25 秒，SSH 总请求限时 90 秒；日志为最后 200、500 或 1000 行（默认 200）的快照，不跟随或轮询，更改行数会重新读取；可按显示出的文字（含时间戳）在本地筛选行，被隐藏的行设置的颜色仍作用于后续行；按终端 SGR 序列显示颜色和粗体等样式（16 色随主题，256 色和真彩色按原值），其他控制序列移除，回车重绘只保留最终内容，时间戳淡化显示，最多渲染 4000 个样式片段。详情只投影必要属性，不查询容器环境或完整配置。启动、停止、重启和配置绑定完整容器 ID，失败后需刷新确认状态，不自动重试。端口同时显示发布与配置映射、未发布的暴露端口；host 网络可跳转现有资源页检查服务器监听。

重启策略和 CPU／内存限制使用 [Docker container update](https://docs.docker.com/reference/cli/docker/container/update/)，只修改当前容器，不改写 Compose 定义；端口和挂载变更需要重建容器。卷详情使用 [volume inspect](https://docs.docker.com/reference/cli/docker/volume/inspect/)，日志使用 [container logs](https://docs.docker.com/reference/cli/docker/container/logs/) 的有限尾部读取。标准输出与错误输出在服务器端合并到同一管道，按 Docker 写出的顺序显示；日志正文中的无效 UTF-8 显示为替换字符，不会使读取失败。

桌面外观独立于客户端设置。“跟随应用”沿用客户端主题，亮／暗选择作用于 Desktop 及其对话框。远端 `~/.arcnix/desktop` 下的 `system.json`、`preferences/` 和 `apps/` 保存分域的 v1 JSON，通过 SSH 读写。首次保存、旧版 `desktop.json` 迁移和同次修改涉及多个文件时，生成一个配置目录并原子切换 `desktop` 链接。单文件修改只上传该文件，在锁内校验读到的配置版本，再原子替换目标文件。单文件保存之间共用当前代目录，上一代对应上次整套发布。并发修改触发重新读取和三方合并，同字段发生冲突时由用户选择。

**Desktop** 将图标流向、起始方向、大小及主文件夹和回收站开关保存在 `preferences/desktop.json` 的 `layout`。在 **Settings → Dock** 可设置 Dock 的位置、样式、图标大小、时钟及固定快捷方式。Dock 设置保存在 `apps/dock.json`。从同一 SSH 桌面的 Files 拖到桌面时，默认或按 Shift 移动，Ctrl 复制，Alt 或 Ctrl+Shift 在远端 `Desktop` 目录创建符号链接。复制和移动继续使用 Files 的文件操作及冲突处理。

桌面 **Region & language** 将界面语言保存在远端 `~/.arcnix/desktop/system.json`，缺失时使用客户端语言。数字和文件大小格式沿用客户端偏好。**Date & time** 仅在识别到系统的时区名称时提供时区选择，在 systemd 上通过 `timedatectl set-timezone` 保存，在其他 Linux 上更新系统时区链接及已有的兼容文件。修改系统时区需要 root 或可非交互使用的 sudo。12／24 小时制可在 **Date & time** 设置。Dock 位于左侧或右侧时，**Dock clock** 可设置星期、日期和秒数。时钟的显示选项保存在 `system.json` 的 `clock` 中。客户端的更新检查位于主设置的 **Updates**。

**Image Viewer** 是 PNG、JPEG、WebP、GIF、BMP、AVIF 和 SVG 的建议默认应用。可以从 Files 双击图片，或在查看器中选择「打开图片」。单张上限为 8 MiB。左右方向键切换同目录图片，滚轮缩放，放大后可以拖动。按 0 适应窗口，按 1 恢复实际大小，R 和 Shift+R 分别向右和向左旋转。按 F 在 Desktop 区域内全屏查看，点击退出全屏按钮或按 Esc 可恢复原窗口。

**PDF Reader** 从 Files、传输页的远端列表或桌面文件选择器打开 PDF。单个文件上限为 64 MiB。使用左右方向键或 Page Up / Page Down 翻页，输入页码并按 Enter 可直接跳转。支持缩放、适应整页或页宽、密码解锁，以及 Desktop 内全屏。本机只读桌面也可使用。

**Text Editor** 是已识别文本格式的建议默认应用。用户设置的文件关联优先。编辑器支持独立标签页、Markdown 预览、保存时检查远程版本和关闭前确认未保存修改。从 Files 或桌面拖入文件会直接用 Text Editor 打开。Text Editor、Code、Player、Image Viewer 和 PDF Reader 使用同一个 Desktop 文件选择器。每个应用提供自己的类型筛选和打开方式。选择器可拖右下角调整宽高，侧栏读取 Files 的位置、收藏、标签及回收站。

**Appearance** 在预置主题和命名主题中选中一套，所选主题和命名主题均保存在 `preferences/desktop.json` 的 `themes`。从 **Customize** 创建主题时，选择浅色或深色方案、图标风格和强调色。新主题继承所选主题的壁纸，可在壁纸选项中更改当前配色方案的壁纸。浅色与深色壁纸不同时，缩略图并排显示。保存时记录选择的颜色参数，显示时使用对应的基础色板生成背景、面板、输入框、边框和文字色，强调色用于高亮和交互状态，并根据背景调整对比度。旧主题的色值覆盖仍可读取。文件夹只保存图案 ID，并按当前主题的风格渲染。

新版读取旧配置或缺少配置文件的服务器时，保留已有设置，缺失项使用当前客户端的默认值。没有可用的主题时沿用旧配置中的壁纸和明暗模式，缺失的明暗模式跟随客户端。默认值在读取时生效，配置在用户保存修改时写入服务器。

App Center 目录包括 Docker、Nginx、Caddy、Redis、PostgreSQL、Git、htop 和 Certbot。连接目标服务器后，检查服务器任务的运行条件、系统包仓库、Snap 稳定渠道和 Docker Compose 可用性。普通用户可以浏览和搜索整个目录，卡片按本机仓库和运行环境显示可用来源。APT 候选还经过依赖模拟。Docker 的安装入口进入同一目录，初始筛选 Compose 应用，可切回全部。按名称安装和仓库搜索保留为辅助入口。

已安装页合并系统包、Snap、Arcnix Compose 项目和通过已知镜像引用识别的外部 Nginx 容器，显示来源和版本或容器状态。已安装的 Nginx 系统包链接到服务管理，各外部容器按完整 ID 打开详情。Compose 项目和独立容器分别提供移除操作，保留数据卷。安装和移除任务完成后重新检测服务器能力并刷新清单。查询失败时仍展示其他来源的结果和对应错误。

系统来源识别 APT、DNF、YUM、Zypper、APK、Pacman；APT 安装继续使用原有事务审核，其他来源在每个目标执行前重新检查管理器。Pacman 升级明确展示为完整系统升级，拒绝单独刷新索引，避免部分升级。软件包名称按管理器验证；不同发行版的同类软件未必同名。Snap 仅在检测到时可用，默认 stable、默认不启用 classic，Certbot 需用户明确允许 classic 才能提交。Snap 身份来自 [Caddy](https://snapcraft.io/caddy)、[htop](https://snapcraft.io/htop)、[Certbot](https://snapcraft.io/certbot) 的发布信息。后台任务可用时，应用中心通过服务器任务安装、升级和卸载软件。普通账号可在提交时提供 sudo 密码。后台任务不可用时，系统包和 Snap 操作可以在新终端中打开命令，由用户按回车执行并按需认证，随后手动刷新清单。Compose 部署仍使用后台任务。

应用中心验证入口：`python tools/app_center_smoke.py`，覆盖浏览时隐藏安装渠道、分类和中文搜索、详情、各来源配置、不可用来源、classic 显式选择、安装来源保持、Docker 共用目录、发行版包名及主题／窄窗口布局。完整安装任务仍由 `tools/desktop_extensions_smoke.py` 覆盖。

Compose 内置 Nginx、Redis、Caddy。定义与清单存放于 `~/.arcnix/apps/<name>/compose.yaml` 和 `arcnix.json`，归原 SSH 用户所有、目录 0700、定义 0600。选择用户目录是为了避免写入其他用户或系统配置、便于按用户备份；Nginx 静态文件位于同一项目 html 目录，命名卷仍在 Docker 的实际存储位置。项目名冲突拒绝覆盖，应用修改前核对审核时的 YAML 摘要；仅列出 Arcnix 管理的项目。使用 Compose v2 的 config 和 up --detach --no-build --wait，配置 restart: unless-stopped；Docker daemon 自身需启用开机启动，可在 Services 中检查。停止／重启／应用通过服务器任务执行，保留数据卷。说明依据 [Compose 生产部署](https://docs.docker.com/compose/how-tos/production/) 和 [Compose volumes](https://docs.docker.com/reference/compose-file/volumes/)。

Disks 通过有限 lsblk/findmnt 查询设备、分区及挂载使用量，不提供分区或格式化操作；未知容量保留为未知，挂载点可打开 Files。Services 合并 list-units 和 list-unit-files，区分运行状态与开机启用状态；enable/disable 不隐式启动／停止。新启动任务以审核后的系统服务执行，用户脚本存放于目标用户 ~/.arcnix/services/<name>/run.sh，单元在 /etc/systemd/system/arcnix-startup-<name>.service，启用后需独立启动。持续程序由 systemd 管理，客户端无需常驻。

Terminal 仅保留一个窗口标题栏，整合标签与操作菜单，不重复服务器地址。布局保存最多 32 个标签的独立 ID、名称、初始目录、活动标签及窗口最大化状态，不保存输出或输入历史。检测到 tmux 后使用独立 arcnix socket 中的 terminal-<id> 会话，重新连接恢复已有屏幕、目录和程序；关闭标签或客户端只分离连接，exit 才结束对应 shell。未检测到 tmux 时只恢复布局，不自动安装。tmux 默认不跨服务器重启保活。

扩展验证入口为 `python tools/desktop_extensions_smoke.py` 和 `cargo test -p arcnix-core --test desktop_extensions_integration --locked -- --ignored --nocapture`（设置下述 WSL 发行版变量）。前者覆盖主题边界、Disks 浏览、Services、Compose 和 DNF/Snap 安装及终端跨进程恢复；后者执行真实 Linux 磁盘查询、私有工具命令、隔离挂载中的 systemd 配置验证，以及真实 tmux 的重复连接。不会安装真实软件包或联系 Docker daemon。

验证入口为 `python tools/docker_desktop_smoke.py`，覆盖实际 SSH 协议交互、受控 Docker 状态、主题跨进程恢复、用户／服务器隔离、权限错误、损坏设置、不完整响应、迟到结果及中文窄窗口。原生 shell 验证不连接 Docker daemon：

```powershell
$env:ARCNIX_TEST_SHELL_DISTRIBUTION='Ubuntu'
cargo test -p arcnix-core --test server_apps_integration --locked -- --ignored --nocapture
```

该专项使用私有临时 home 和受控 Docker 可执行文件，执行真实 POSIX shell，核对文件原子替换、权限、链接拒绝、含空格／中文的路径、明确本机连接及 CLI 参数，完成后清理自己的目录。

桌面应用打开、切换、最小化、关闭与最大化采用 160–240 毫秒的过渡，打开与最小化分别从启动图标方向展开和朝 Dock 收拢。Rust 通过 desktop-motion-state 仅发布可见性、应用、连接世代与窗口布局；浏览器使用独立窗口的 View Transition 合成快照，不复制应用 DOM 或终端内容、不重建会话，也不等待 SSH 数据。点击仍只交给原有处理器一次；连续点击跳过旧视觉并保持原生操作顺序，切回首页或更换连接立即结束旧过渡。缺少 View Transition 时使用轻量入场，捕获失败仍保留原操作；prefers-reduced-motion 动态关闭两种效果和图标动画。API 行为参考 [startViewTransition](https://developer.mozilla.org/en-US/docs/Web/API/Document/startViewTransition)；专项入口为 `python tools/desktop_motion_smoke.py`，另由 `server_desktop_smoke.py` 和 `app_center_smoke.py` 回归窗口与终端、应用中心流程。

每个桌面应用在自己的 `~/.arcnix/desktop/apps/*.json` 中保存普通窗口的位置、宽高、参考工作区宽高和最大化状态。底部 Dock 从工作区扣除高度，左右 Dock 从相应侧扣除宽度。窗口布局、最大化和原生视图裁切共用这块工作区。自动隐藏保留 Dock 的占位，避免显示 Dock 时窗口移动。拖动或缩放从窗口当前显示的矩形开始，结束后将位置、宽高和工作区尺寸一起保存。工作区宽度和高度分别计算。空间小于原尺寸时，窗口在对应方向贴合两边。用户拖到边缘外的部分在工作区扩大时优先露出。窗口能完整显示后，中心尽量保持在参考工作区里的相对位置，由工作区边缘限制最终位置。Files 通过 SFTP 查找主目录及已有的 Desktop、Documents、Downloads，侧栏开关、收藏、目录标记和自定义文件夹图标都保存在 `apps/files.json`。`tools/desktop_windows_smoke.py` 验证了拖动、跨尺寸恢复及客户端重启。

服务器首页右上角齿轮进入编辑。桌面标签右侧可将服务器桌面铺满应用内容区域；桌面顶栏按钮或 Escape 恢复原布局，弹窗和菜单优先处理 Escape，终端控件与 SSH 会话保留。桌面内“资源管理器”复用现有 SFTP 文件操作，仅显示远程目录，与“传输文件”共享路径、筛选和选择；下载使用当前本地目录，保存位置收进工具栏 `?`，也可跳转到双栏选择本地目录。日志工具栏放大镜重新检测日志源并读取日志，刷新按钮只读取当前查询。`python tools/server_desktop_smoke.py` 覆盖这些入口、实际文件内容、全屏与弹窗层级、语言和窄窗口。

文件区右键菜单与工具栏“…”共用 Rust 操作入口，项目菜单按当前选择显示；右键多选中的项目保留全部选择，右键其他项目单选，空白处清空选择并显示目录操作。复制所选路径使用按显示顺序排列的完整路径，以换行分隔；本地路径移除 Windows 内部命名空间前缀。属性不递归扫描文件夹大小，多选最多展示 100 条路径。

Shift+F10／菜单键打开菜单，方向键和 Home／End 移动焦点，Escape 关闭并恢复焦点；F2 重命名，Delete 移入回收站，Shift+Delete 打开永久删除确认，Alt+Enter 查看属性，Ctrl+Shift+C 复制所选路径，F5 刷新。路径输入框保留正常的文本编辑行为。`python tools/file_context_smoke.py` 会自行启动隔离的回环 SSH 服务，验证本地、SFTP 和键盘交互，不读取默认配置或真实服务器凭据。

桌面 Files 的「位置」包含回收站。回收站列表显示原路径和删除时间，项目右键可还原或确认永久删除。文件夹右键可在新标签页打开。Files 标题栏的 ＋ 和 Ctrl+T 新建标签页，Ctrl+W 关闭当前标签页。标签页保留各自的路径、浏览历史和选择，拖出窗口后在桌面上形成独立的 Files 窗口，拖入另一窗口后合并。使用 `python tools/files_tabs_smoke.py` 验证标签页和回收站交互。

Files、Terminal、Browser 和文本编辑器共用桌面标签拖动逻辑。拖到桌面空白处可拆窗，拖到同一应用的另一扇窗口时，标签栏会让出插入位置，并以竖线标记。拖到窗口内容区则追加到标签栏末尾。松开即可并窗，按 Esc 可以取消。拖动只改变标签的位置，终端会话、浏览器页面和文档草稿都跟随原标签。使用 `python tools/window_tabs_smoke.py` 验证终端、浏览器和文本编辑器的拆窗与并窗。

文件传输的本地和远程栏分别提供“移入回收站”“永久删除”和“打开回收站”。远程栏的“打开回收站”进入 Files 的回收站位置。本地使用系统回收站，macOS 通过 Finder 管理回收站。远程遵循 FreeDesktop Trash 规范，在用户数据目录的 `Trash` 或原挂载盘的用户回收站保存文件和 `.trashinfo`。无法完成移动时保留文件，还原时原路径已被占用则提示冲突。`python tools/trash_smoke.py` 验证两个界面及远程元数据的互操作。安装了 Ubuntu WSL 的 Windows 主机可追加 `--ubuntu-gio`，使用 Ubuntu 的 `gio trash` 生成还原用的记录和文件。

永久删除弹窗冻结当前目标快照，显示本地／远程及完整路径，明确不会移入回收站。执行前检查类型、大小及修改时间，合并选中的父子项并预扫描全部树；拒绝根目录和路径穿越，深度最多 64 层、总数最多 100000 项。符号链接及 Windows 目录联接只删除链接本身。执行按子项优先顺序再次检查类型与父目录，新到达的内容不会被递归纳入，非空目录会报错。SFTP 使用 unlink/rmdir，不调用 shell 或系统 SSH。文件系统操作不具备事务性，错误报告已删除数量及失败路径，刷新目录且不自动重试；同大小、同时间的替换及检查与执行之间的并发修改无法完全检测。

```powershell
python -m pip install --target artifacts/python playwright paramiko
python tools/ui_smoke.py
python tools/ui_smoke.py --packages --legacy-host-key --isolated-crypto-runtime
python tools/navigation_smoke.py
python tools/server_desktop_smoke.py
python tools/operations_smoke.py
python tools/file_context_smoke.py
python tools/file_options_smoke.py
```

Windows 综合与专项脚本均自行启动独立 SSH fixture、配置和 WebView，直接连接本机调试接口，不下载浏览器，不使用默认配置或真实服务器，也不执行真实 apt。`ui_smoke.py` 的基础模式检查文件、键盘、站点和重启布局；`--packages` 还覆盖资源、日志、服务器托管的软件任务、SFTP 冲突及 SFTP 不可用时的能力隔离。旧标志名继续兼容，但无需手工准备 `artifacts/fixture.json`。`--legacy-host-key` 核对原 RSA 信任记录在新协商下保持，`--isolated-crypto-runtime` 仅为桌面子进程限制 PATH 到 Windows 系统目录。

综合脚本已适配当前导航：未选择／未连接时不访问单机模块，连接后从 Servers 工作区进入；安装统一审核并提交服务器任务，断开和切换按钮保持可用。站点与分栏状态按固定测试身份核对，不依赖分组后的行号或配置列表顺序。每轮写入独立的 `artifacts/ui-smoke/run-<time>/`，失败时先捕获页面与截图再关闭 WebView；`latest-files.json` 和 `latest-packages.json` 分别指向最近通过的对应模式。专项继续保留各自 artifacts 目录。结束时只关闭自己的进程；界面原语约定见 [docs/ui-design.md](ui-design.md)。

## 文件任务与属性

Files 窗口的齿轮设置保存默认视图、图标大小（24–96 px）、排序和显示列。「显示隐藏文件」是全局开关，Ctrl+H 切换同一设置。显示隐藏项时，其图标使用 60% 不透明度。工具栏的视图按钮、“…”菜单、列标题和 Ctrl+滚轮修改当前文件夹。再次进入目录、在另一标签页打开或重启后均使用该目录的配置；没有单独设置的项目继续继承默认值。“使用默认视图”清除当前文件夹的覆盖。名称列固定显示，大小、类型、修改时间和权限列可选。本机目录按路径保存，远端目录按服务器和路径保存。旧配置中的服务器分栏偏好作为默认列的兼容回退。

递归删除先扫描再按子项优先删除，进度经限频且非阻塞的事件通道显示。取消、弹窗 X、Escape 均请求停止，弹窗立即关闭，剩余请求在后台收尾；当前 SFTP 请求可能等待网络超时（15 秒），之后不再删除下一项。取消不是回滚，已删除内容无法恢复，日志记录部分数量。连接变更也触发取消；断连和过期请求必须返回匹配任务的完成事件，不能遗留禁用状态。SSH 工作队列串行执行，删除收尾期间文件写入操作等待。

属性窗口显示名称、路径、文件字节数、修改时间和 UID／GID；目录大小不递归统计。远程权限使用 SFTP lstat/setstat，支持多选、3／4 位八进制值和 Sapid 读写执行复选框，复选框保留特殊位。混合权限要求明确输入，提交前逐项核对旧模式和类型，拒绝符号链接及链接父目录，不递归修改子项、不变更所有者或文件内容；错误可能部分完成，必须重新打开属性核对。Windows 本地只显示基本信息，未提供 ACL 编辑。保存权限期间仍可关闭并请求取消。

`python tools/file_options_smoke.py` 自行创建独立 SSH 服务、配置和 WebView，验证慢目录扫描／执行取消、真实权限读写、子文件保留和多选权限，以及跨服务器、跨进程的列配置恢复；不接触真实服务器或默认配置。

## 服务与常用命令验证

服务管理通过工作区 SSH 查询已加载的 systemd 服务；不使用 systemd 时显示原因。软件检测、搜索、已安装列表、服务列表／详情和日志仍为按需只读请求。软件安装、APT 索引更新、服务启动／停止／重启和保存命令的运行均打开统一 ScriptRun 表单，预选当前服务器，并允许增加其他已信任目标。任务连接独立于工作区，可能需要重新提供认证信息；审核预检查后由服务器执行。

命令库仍保存在本机配置中，最多 200 项，每项最多 8 KiB；普通与参数命令共用全局任务的字面量展开、预览、持久结果及最近十批历史。安装与索引更新保存类型化动作并重新检测 APT、重建执行命令；服务动作核对每个目标的服务单元后生成固定操作。工作区 worker 不再提供 PackageApply、服务／命令 Run 等变更通道，也不保留旧的五分钟客户端执行器。切换服务器、断开工作区和关闭客户端不会停止已接收任务；交互程序仍使用 Terminal。

`python tools/operations_smoke.py` 自行启动两个隔离 SSH peer 与独立桌面，覆盖原单机入口、多目标安装、关闭重开、查询原结果、索引更新、服务操作与状态查询、命令编辑删除、参数、冲突锁和中文窄窗口。fixture 只模拟软件和服务变化，不执行实际 apt 或系统服务操作。实际 systemd 服务验证使用 `hosted_tasks_integration` 中有时限的独立测试 service，不操作系统已有服务。


## 全局脚本与服务器任务

### 参数类型与本地预设

`script_parameters.rs` 为独立、未加引号的 `{{name}}` 参数定义文本、整数、端口、服务器绝对路径、单选和布尔值规则。可配置标签、说明、必填、默认值，以及整数上下限和选项列表；未声明的旧参数仍为必填文本。整数和端口使用规范十进制，路径允许根目录并拒绝空组件、`.`、`..` 和尾斜杠。类型检查不会探测服务器文件是否存在，也不承诺脚本幂等或回滚。可选空值始终展开为一个 `''` 参数，不省略位置；所有值仍单次展开为 Shell 字面量，不解释表达式。展开后的 Snippet 清除参数定义，任务版本绑定原始规则。

作者需点击 Configure parameters 解析正文占位符，可逐字段设置规则。原始非法上下限保留在会话编辑状态，保存前拒绝；更换类型或明确重新配置时重置该草稿。默认值随脚本保存在本机并可导出分享，因此不应放入密码／令牌。运行表单始终从默认值开始，支持类型控件、错误提示和重置。

预设独立存于 AppConfig.script_presets，仅允许显式标记 allow_preset 的字段，每脚本最多 10 项、全局 2000 项、每项最多 8192 字节，并受正常配置 4 MiB 限制。官方／用户来源由 Template 私有属性确定；用户伪造 builtin 编号不获得官方预设或能力。保存新预设拒绝重复名称，覆盖需明确选择并更新；载入将未保存字段重置为当前默认值，不沿用上次输入。脚本正文、名称、权限或参数规则变更使旧摘要失配，禁止直接载入；更新操作使用本次表单值并重新绑定。脚本保存、删除和包导入时清除孤立／不再允许／不再符合规则的值，保留尚有字段的旧摘要；删除全部已记字段会移除该预设。官方定义升级引起的不兼容预设作为有界失效记录保留，可删除或明确更新，不阻塞客户端启动。

预设不会自动载入、不会选择服务器、不会包含 SSH 或 sudo 凭据，也不会进入脚本包；这不等于加密凭据保管。官方 Directory usage 提供可存预设的路径参数，其余官方模板按现有作用范围执行。任务预检查和服务器执行流程保持不变，不新增后台驻留或定时调度。`tools/script_parameters_smoke.py` 覆盖类型表单、预设、v2 分享及双服务器重启查询。

### 脚本包导入与分享

`script_bundles.rs` 定义便携 JSON：顶层只有 `kind: "arcnix-scripts"`、`version` 和 scripts；每项包含 name、description、command、administrator，可选 parameters。无类型定义时导出 v1，包含类型定义时导出 v2；v1 输入仍兼容，v1 不接受非空类型定义。文件最多 4 MiB，1–200 项；命令复用 8192 字节及字面参数规则。严格拒绝未知字段，包括外部 id、服务器信息、installation／drill 等类型化定义。导出不包含运行时参数值；导入生成普通用户脚本，不由名称或文件内容授予官方能力。

读取只捕获有界文件内容及 SHA-256，用户选择后再生成独立 ImportPlan。相同定义跳过；默认复制并生成新编号，重名副本追加有界名称。显式替换只允许本地唯一同名项，并保留其编号；名称按去除首尾空白后的小写匹配，歧义拒绝。预览包含旧／新正文及权限。计划绑定整个脚本库摘要，库发生变化时拒绝保存；来源文件变更不重新读入，保存的始终是审核过的定义。合并使用提交时的当前配置，保留其他设置，并通过 `ConfigStore::check` 预先检查与 save 相同的模型及 4 MiB 序列化限制；最终仍使用原原子配置保存。

导出先复制用户脚本到会话草稿，允许编辑分享副本的名称、说明、命令和权限，供用户手动移除写在正文或说明中的敏感值；这不修改原库，也不自动识别或保证清除任意秘密。选择项通过验证后冻结成 ExportPlan，显示目的地、摘要及完整定义，另行点击写入。目的目录须已存在，文件名不含路径分隔、流名称、控制字符、尾部点／空格或 Windows 保留设备名。临时文件与目的文件同目录，Unix 权限为 600；完整写入和 sync 后复用 no-replace rename 发布，失败仅清理自身临时文件，不删除已有目的地。客户端被强行终止可能遗留临时文件，但不将部分写入直接作为最终文件。Windows 命名约束参考 [Microsoft 文件命名说明](https://learn.microsoft.com/en-us/windows/win32/fileio/naming-a-file)。

`script_exchange_ui.rs` 在全局脚本中心提供入口，不要求活动服务器。导入和导出均先预览再提交；默认选择非相同导入项，支持批量选择／清除。所有草稿、读取路径及计划仅在会话内存保存，取消或离开页面清除。导出只向新文件发布；需要更新已有文件时选择新名称。文件浏览复用现有原生文件／文件夹选择器，并保留手动路径输入；不调用 Shell 或运行被选择的文件。此功能没有调度或后台常驻。

Scripts 独立于当前服务器连接，提供 11 个官方模板（含 Python 3 安装）和现有命令库对应的 My scripts。用户可以新建、编辑、删除、复制模板；脚本中独立且未加引号的 `{{parameter}}` 生成运行参数，展开时作为单个 shell 字面量引用，禁止嵌入引号或拼接到其他 shell 单词。参数及脚本正文不可存放凭据。

运行时选择 1–32 台已保存主机指纹的服务器，逐台提供 SSH 密码／私钥口令及可选 sudo 密码，并选择 1、3、5、8 的预检查／提交并发上限。服务器接收后立即释放提交名额，后续服务器不等待前台任务运行结束；实际运行中的服务器任务数可以超过此数。预检查使用独立连接，检查服务器 systemd 能力和权限，安装模板复用 APT 精确包校验与禁止移除软件的模拟预览。核对各目标计划后才执行就绪目标；停止后续目标不会终止已经提交的服务器任务。当前一次只允许一个批次，活动目标阻止对应单机软件／运维任务，切换全局页面不影响任务。

批量任务由服务器 systemd 管理的临时 service 执行。客户端不部署常驻 Agent 或本地调度器，关闭客户端后已经提交的任务继续运行。工作负载按脚本声明运行于 root 或原 SSH 用户；启动 systemd service 需要 root 或 sudo。日志及退出结果保存在远程 SSH 用户的 `$HOME/.local/state/arcnix/tasks/<task-id>/`，完整日志保留在服务器，客户端仅保留有界尾部。最近批次、桌面任务窗口和服务器记录中的任务输出按终端 SGR 序列显示颜色和样式，规则与 Docker 日志相同，颜色在同一任务输出内跨行延续。任务运行一小时后客户端停止自动查询，服务器继续管理进程。

启动请求发送期间状态为 Submitting，收到 systemd-run 的成功响应后才发布 Running 并释放提交名额。Submitting 表示尚未确认接收，关闭客户端可能中断提交；重启后与 Queued／Running 一样保留 Unknown 并查询原编号，不能因为未收到响应就重复执行。配置恢复入口同时排除 Submitting 来源。查询到服务仍活动时继续显示 Running，任务退出仍以服务器结果为准。

统一 ScriptRun 表单使用 `task_target_picker.rs`，核心纯选择规则位于 `target_selection.rs`。`Template::allows_target` 统一备份策略、清理及残留处置的 ID 范围；服务器端预检查仍按原端点、指纹和冻结来源核对，不把客户端筛选当作授权。搜索最多 256 个字符，按空白分词、忽略大小写，所有词都须命中名称／地址／账户／端口／实际分组名的组合；筛选包括所有分组、未分组、指定分组和只看已选。

“选择当前可见的已信任服务器”追加到原集合，先完整校验再原子提交；不部分添加，不自动挑选重复端点的账户。上限为 32 个目标，每个大小写不敏感的主机字符串＋端口仅允许一个账户。单项选择与实际预检查也应用信任、范围和端点约束，未知或范围外 ID 不能被忽略后继续执行。清除可见项只移除当前筛选范围；“查看已选服务器”清空搜索／分组条件并仅显示全部选择，隐藏选择归零后才允许预检查。

筛选与目标选择不落盘。隐藏行销毁后重新出现时，SSH／sudo 密码字段绑定同一服务器 ID 的本次内存值；取消该项、清除可见项／全部或关闭表单会移除对应凭据。失败的批量选择保持已有目标和凭据不变。新模板重置过滤器，工作区入口预选当前服务器、备份入口预选策略服务器的行为保留；服务器执行与并发策略不变，没有增加本地后台调度器。

Tasks 将最近 10 个批次写入配置文件旁的 `<config-stem>.tasks.json`，预检查计划、目标端点和原主机指纹固定在任务记录中。重启将未确认执行结果标记为 Result unknown；“Query server result”使用原指纹重新认证并查询服务器日志和退出码，不重新提交任务。编辑了服务器地址或用户名时拒绝查询旧任务。损坏的历史文件保留并禁止新任务覆盖。凭据不进入配置或任务历史。

Windows 上，未允许删除共享的读取句柄可短暂阻止历史文件替换，规则见 [CreateFileW 共享说明](https://learn.microsoft.com/en-us/windows/win32/api/fileapi/nf-fileapi-createfilew)。保存仍使用同目录独占临时文件、完整写入及同步后 rename；仅在替换返回 5／32／33 时最多等待 250ms，再尝试同一份已冻结内容。其他平台保留一次 rename，其他错误立即返回；持续占用保留原文件、清除本次临时文件并沿用只读／提交保护，不改变远程任务。原生用例 `windows_history_save_tolerates_short_readers_and_preserves_locked_files` 验证短暂占用释放、持续占用时原字节与临时文件清理，以及释放后的正常保存。

本阶段不实现依赖桌面常驻的定时调度、持续监控或自动维护；后续如添加计划备份等能力，必须由服务器端工具持有计划和数据，客户端仅配置、查看进度和恢复结果。

### 服务器任务记录浏览

Tasks 提供 Recent batches 与 Server records 两种视图。后者按独立选择的 SSH 账户浏览 `$HOME/.local/state/arcnix/tasks`，不依赖当前工作区或本地最近十批任务。每个目标单独认证，固定主机指纹、地址、端口和用户名；翻页与日志查询重新建立连接，重新连接前核验库存身份未变化。凭据只在内存保留，离开 Tasks、切回最近批次、准备新任务或主动忘记时清除；在途读取可能继续到完成或超时，不宣称立即中止。

新任务初始化时写入私有 `record.json`，包含版本、任务编号、名称、类型、模板版本和服务器创建时间；恢复演练还保存公开的执行服务器与 Description，元数据总量最多 8 KiB。普通脚本参数、脚本正文、配置正文及认证数据不进入元数据。旧任务没有元数据时仍以编号和目录修改时间展示；损坏或编号不匹配的元数据不作为标题。元数据不授予停止任务、删除文件或恢复配置的权限。

查询使用 POSIX shell、GNU coreutils／findutils、sort 和 timeout，不需要 Python、SFTP 或 sudo。列表按任务目录修改时间倒序，每页 100 条，只遍历直接子目录；并发创建记录可能导致翻页位置移动。查询以绝对路径工作，不依赖 SSH 初始工作目录。根路径首次解析后固定；后续响应根路径变化拒绝更新，要求重新连接。直接根目录或任务目录符号链接被拒绝，日志、结果和元数据须为可读普通文件且无额外硬链接；不递归读取其他目录。

版本化列表响应必须有完整头尾、记录数量及匹配页码，最多 1 MiB；详情校验任务编号与根目录，只读取日志最后 48 KiB。日志大小是该文件的逻辑字节数，不是服务器记录的实际总磁盘占用。读取失败保留上次快照及其时间，刷新不重新提交任务。服务查询最多 2 秒，服务器查询总体限时 25 秒，SSH 流读取限时 30 秒；大量记录或服务管理器响应缓慢时可以失败，不把部分结果视作完整列表。

运行／停止中的服务优先于已保存退出码。无法读取服务管理器、状态不识别、失败服务与成功退出码矛盾，以及无确认结果时均保留 Result unknown；服务管理器不可用仍可查看保存日志。所有数据是查询时快照，不是持续监控。浏览结果和日志仅存会话内存，不写入最近批次或 `backup_evidence`，退出码为零不等于恢复验证或应用健康。Tasks 当前不提供任务终止；容量及精确审核清理见记录存储章节，root 私有配置版本从 Configurations 的服务器恢复记录查看。

### 全局任务的服务器操作锁

全局脚本、安装、备份、恢复和配置发布使用服务器共享的 `/run/arcnix/operation.lock`，需要 util-linux `flock` 和 GNU `stat`。启动器以 root 创建并核对目录的 root／755、文件的 root／644 和非符号链接属性；普通用户工作负载只打开只读描述符，仍可取得 Linux 排他 flock，无需授予锁文件写权限。锁只包含运行时协调信息，不存放脚本或凭据；不是客户端后台进程。

预检查以非阻塞方式核验锁，但不预留执行名额。实际 systemd 服务在执行工作负载前再次加锁，冲突时写入退出结果 75，不执行工作负载；不排队等候，不自动重试。锁属于服务器内核和持锁服务，跨 SSH 账户、客户端实例及桌面重启生效。Diagnostics 使用明确的只读执行类别，不取得该排他锁；自定义脚本不能自行声明免锁。不同服务器仍可独立运行。

保持同一个锁 inode，不因锁文件存在而判断正在运行，也不删除锁文件“解锁”。正常退出、失败或持锁进程被终止后由内核释放；SIGKILL 等情况仍可能没有退出结果，应按未知结果核验，锁已空闲不能证明操作未执行或已经成功。锁是协作机制，不约束服务器上的手工命令、其他产品或故意绕过锁的脚本。

保护从使用本执行器的新任务开始，Software／Operations 入口也已统一接入。升级前由旧执行器提交的任务不持有新锁，仍需查看原任务和实际系统状态。不将这项检查等同于所有服务器写操作隔离，也不承诺服务器重启恢复。参考：[util-linux flock](https://man7.org/linux/man-pages/man1/flock.1.html)。


## 全局备份与恢复

Backups 为不依赖当前服务器选择的全局页面。策略保存名称、仓库地址、服务器密码文件路径、源目录、排除规则、目标服务器及每组保留快照数，不保存仓库密码。可一键进入 restic 安装模板；密码文件需由服务器管理员准备为 400／600 权限，并在独立位置保管密码副本。

支持手动初始化、目录备份、完整仓库数据检查、保留策略和恢复。初始化／仓库检查默认选择一台服务器，非备份操作限制为逐台提交，已接收任务仍独立运行，不保证运行期间串行；共享远程仓库仅允许从一个目标初始化。restic 保留原生仓库锁，锁冲突报告失败，不自动解除锁或重试。每个快照写入 `arcnix-policy:<id>` 和 `arcnix-server:<id>` 两个标签，列表和保留操作按两个标签共同筛选。完整检查使用 `check --read-data`；保留先执行 dry-run，确认后 forget，不自动 prune。

恢复从快照列表选择完整 ID，预检查再次核对来源标签。恢复目录必须为源目录和本地仓库之外的新绝对路径，预检查及执行均解析符号链接检查重叠，最终以不带 -p 的 mkdir 拒绝已有目标，再使用 `restore --verify --json`。快照中的绝对路径层级重建于新目标下，不替换原目录。JSON 进度在任务中心显示百分比、文件和字节数量；原始日志仍保留。

Recover on another server 是显式异机恢复流程。来源从策略保存的服务器编号选择，删除服务器配置不会删除这些编号；来源无须在线或具有主机信任。仓库访问端独立选择当前库存中已信任的服务器，复用目标搜索的名称／地址／账户／端口／分组多词匹配。凭据只用于访问端，读取命令和解析都按原来源标签筛选，不连接原来源。切换来源或访问端清除凭据、快照、文件及选择，关闭后晚到事件由 serial 拒绝；仅改变搜索不会改变已选访问端。

文件及 PostgreSQL 恢复、恢复演练可通过 `Template::for_cross_server_recovery` 显式允许策略外目标。该标记为私有模板状态，只能为类型化恢复设置；`allows_target` 仍核对恢复动作，普通恢复、备份、初始化、检查、保留与清理不因此扩大范围。统一目标验证继续要求固定主机信任、原端点、每批最多 32 台和端点去重。实际目标保存在 Task.targets，来源仍在原 Action／TaskInfo／演练 Description 中；策略服务器列表和策略版本不作临时改写。查看或重新查询旧任务不会恢复该模板能力或重新提交。

访问端默认成为恢复表单的已选执行端，可另选多个已信任目标；每台重新认证、预检查和审核。仓库地址、密码文件及数据库认证引用沿用策略，工具和目录必须提前在各目标准备，客户端不转发数据或复制凭据。完整恢复也提供可读的来源／执行端／快照／新目标审核，选定恢复保留字面路径审核。未知来源编号的仓库内发现、原路径接管、目标环境自动准备及异地仓库矩阵另行完善；异机入口不承诺普通本地仓库在原磁盘损坏后仍可访问。

快照的 Browse files 使用 `snapshot_files.rs`／`.py`，通过 Python 3.8+ 调用 `restic ls --json <完整编号>:<目录> /` 获取直接子项，不读取文件正文、不要求 SFTP。同时兼容 `message_type` 和旧 `struct_type`，核对快照 ID、策略／来源标签、目录、分页及直接子路径。每页 100 项，单目录最多 10,000 项／16 MiB 原始元数据，单行最多 256 KiB，错误输出最多 64 KiB；每次子查询 30 秒、完整请求 45 秒，SSH 最长 60 秒。通过 selectors 同时读取两个输出流，拒绝不完整响应；失败先 SIGINT 并最多等待 3 秒供 restic 释放读锁，再终止未退出进程。读取可能使用 restic 正常缓存和原生仓库锁，不删除或变更快照。

文件选择可跨页及目录，最多 100 个路径、合计 4096 字节、涉及最多 32 个父目录；生成命令仍受 8192 字节上限约束，过大时需要减少选择。仅普通文件和目录可直接选择，目录包含其后代，其他类型只展示。路径须为规范绝对路径，支持 Unicode、引号、反斜杠及通配字符，但拒绝控制字符、重复分隔符和 .／..；root 只用于浏览，不作为选定恢复路径。读取失败保留原页与采样时间、清除选择并禁用恢复；成功读取后可重新选择。访问绑定原配置端点和主机指纹，只存在于备份浏览内存；关闭、导航、切换服务器或忘记时撤销权限，serial 拒绝晚到结果。

`Action::Restore.paths` 空列表表示原完整快照恢复，非空列表在预检查及执行时按父目录查询不可变快照、核对全部选中项存在且类型可恢复，再创建新目标。字面路径逐字符转义 Go filepath.Match 的 `\\[]*?` 后经 shell 引用传入 `--include`，不执行变量、通配或表达式扩展。实际执行先在子 shell 完成复核，然后在主进程创建目标并运行 restic，避免读取程序的 exec 提前结束整个恢复。审核只显示来源、目标、选中清单、校验行为及最终 restore 命令。结果保留路径范围及 origin_server，旧记录缺省为空；摘要区分完整／选中恢复。客户端不承担执行或调度，数据回到业务原位置、应用接管和定时演练需另行设计。

仓库可为绝对路径、`sftp:user@host:/path` 或 `s3:https://host/bucket/path`。拒绝地址中的密码、查询串等凭据形式，后端认证从服务器环境／标准凭据文件读取。文件备份不承诺活跃数据库一致性，数据库应切换为原生导出类型，不能把活动数据目录当作普通目录备份。未建立本地常驻计划或全天监控。


## 数据库导出、恢复与确认记录

策略可选择目录、PostgreSQL、MySQL/MariaDB。数据库策略的 Source directory 是服务器上预先准备的私有暂存父目录，认证文件为 pgpass 或 MySQL 客户端选项文件，权限须为 400／600。客户端只保存连接信息和文件路径；不读取文件内的口令。数据库与用户名称采用最多 63 字节的 ASCII 标识符，避免 libpq 将数据库名解释为连接字符串。

PostgreSQL 使用 `pg_dump --format=custom`，校验归档可读取并计算 SHA-256。MySQL/MariaDB 使用 `--single-transaction --quick --skip-lock-tables` 导出数据、例程、事件和触发器，仅允许 InnoDB 表；导出期间应避免并发 DDL。预检查和执行均要求对精确数据库或全局直接授予 SELECT，拒绝仅有部分表可见性的账户，避免静默遗漏。角色／通配授权不自动推断，建议使用明确授权的备份账户。原生客户端还需要读取其余被导出对象的权限，工具出错时整个任务失败。

每次导出以原子 mkdir 创建固定策略工作目录，既保持 restic 快照 paths 分组稳定，又避免两个客户端同时覆盖同一导出。输出先写 partial，成功后重命名，校验后才调用 restic。退出时仅删除本次已知文件并移除目录，不递归删除其他内容。异常中止留下的工作目录会阻止重试，需先核验上次服务器任务。密码文件不进入该工作目录。服务器 systemd 服务持有完整执行过程，关闭客户端不影响导出或上传。

PostgreSQL 快照可选择恢复到新的数据库：重新核对快照标签和归档路径，读取并校验归档及摘要，要求目标账户有 CREATEDB，createdb 原子拒绝已有目标，再以 pg_restore 单事务执行。目标名称须不同于源库；不导入原所有者和授权，失败时保留新库供检查。该结果不代表应用已经恢复服务。MySQL SQL 导出目前恢复为文件，由操作者在受控环境验证导入，界面不自动向 MySQL 服务器导入 SQL。以上为单库逻辑备份，不包含集群角色、表空间或 PITR。

`backup_evidence` 与最近 10 个任务列表分开保存：最多保留 512 组策略／服务器／操作记录，每组区分最后尝试与最后成功。记录包含策略版本、原服务器地址／指纹、任务开始及确认时间、退出码、仓库、快照或恢复目标。新失败及旧任务的晚到查询不会抹除较新成功记录；策略或服务器身份变化会标明旧配置。客户端尚未查询到服务器结果时，不生成成功确认。时间展示以成功任务开始时间为准，避免把晚到查询当作刚完成的备份。

## 跨服务器配置发布与恢复（历史设计，桌面页面已移除）

Configurations 为全局入口，支持完整 Nginx 配置和自定义应用配置。发布目标是现有的、无符号链接的真实绝对路径常规文件，且只有一个硬链接；候选为最多 128 KiB 的 UTF-8 文本，CRLF 统一为 LF。自定义校验接收私有候选文件作为 `$1`，重载及健康检查接收生效路径作为 `$1`；这些命令以 root 运行，必须能在服务器独立完成。Nginx 使用 `-t -c` 校验、`systemctl reload` 重载及 HTTP 2xx／可选包含文本检查，不自动启动或重启服务。

预检查需要 SFTP、Python 3.8+、root／sudo 和 systemd。候选、请求描述及经过 SHA-256 核对的执行器先私有上传到 SSH 用户的 staging 目录；提权后创建 `/var/lib/arcnix/configurations/<task-id>`，保存原始版本、候选、校验日志及版本化 manifest。状态目录和父级必须由 root 控制，目录模式为 700。候选和原始文件数据及阶段记录执行 fsync；执行器按任务冻结，客户端退出或升级不会替换正在执行的服务器代码。

预检查会创建私有记录及同目录的临时校验文件，但不改动生效配置，也不重载服务。每台服务器生成独立差异、原／新摘要及属主／权限计划。差异只在本次会话内存显示；任务历史不保存配置正文或差异。命令、健康条件、路径和摘要是持久元数据，不能包含口令或令牌；敏感参数应引用服务器文件。客户端重启后显示结果未知，通过原端点和指纹查询任务，不重复提交。

执行使用服务器按路径的 flock，核对预览时的摘要、设备／inode、大小、修改／变更时间、属主及模式，并在实际替换前再次检查。候选在同目录写入并同步后原子替换，保留属主、权限及扩展属性；清除原文件没有的默认继承 ACL，避免新增访问权限。随后重载并在 3–300 秒配置时限内做健康检查。HTTP 检查在受父进程超时控制的短命进程中执行，DNS、TLS 或持续慢速响应不能无限占用该检查；进程结束有额外清理宽限。校验／重载命令每次限 30 秒，私有日志每项最多保留 256 KiB。

发布失败后只在仍匹配本任务安装版本时恢复之前的文件，再重载并检查之前版本的服务健康；HTTP 恢复检查不要求新版本的预期响应文本。分别报告文件状态已恢复、服务恢复已确认、恢复未确认等阶段。自定义健康命令也必须能检查旧版本。备份保留在服务器；异常不会删除恢复依据。

“恢复之前记录的版本”从原记录取回原始内容和元数据，生成一份新的差异、当前版本备份及恢复任务，须重新审核。允许恢复后来手工编辑的文件，也允许目标已被删除；执行仍锁定本次恢复预览的版本，缺失目标采用不覆盖已有文件的原子创建。若有文件在创建瞬间到达，不把它当作本任务安装的文件去删除。恢复操作本身失败时尽力返回恢复前状态，保留所有记录供检查。

本次是单文件操作，不覆盖引用文件、任意自定义命令的外部副作用，也不是与所有手工写入者隔离的文件系统事务。SIGKILL、服务器崩溃／重启和底层存储损坏不保证自动恢复；已同步的原始版本、manifest 和日志提供显式恢复依据。任务记录和备份暂不自动清理，最近 10 个批次以外的服务器记录可由管理员按路径核验。恢复未确认时先检查该记录中的 `manifest.json`、`error.log`、`validation.log`、`reload.log` 和 `health.log`，不要直接重跑旧任务。

批量调度限制的是提交连接，提交成功后各服务器独立执行。配置任务观察到失败会停止尚未开始的提交；已经开始／完成提交的目标仍自行完成或恢复，不提供跨服务器原子提交。当前内置发布器为完整 Nginx 配置；其他应用使用明确的自定义校验、重载和健康检查，SSH 配置校验仍可从 Diagnostics 按需执行。

参考：[systemd-run](https://www.freedesktop.org/software/systemd/man/256/systemd-run.html)、[Python os 文件操作](https://docs.python.org/3/library/os.html)、[Nginx 参数](https://nginx.org/en/docs/switches.html)。

### 服务器配置恢复记录

Configurations 的 Recent configuration changes 保留最近本地批次；Server recovery records 独立选择 1–32 台已信任服务器，读取固定 `/var/lib/arcnix/configurations`。每个端点只选择一次，账户与主机指纹绑定，查询重新建立 SSH 连接。读取需要 Python 3.8+ 和 root／sudo，不要求 SFTP；发布及恢复继续使用原有 SFTP、systemd 和操作锁流程。管理员口令仅通过 sudo stdin 传递，解释器入口关闭 stdin，不读取服务器认证文件。

`configuration_records.py` 是每次查询发送的固定只读程序，不安装常驻服务，不写任务或配置记录，不执行保存的校验、重载、健康命令。程序要求根目录和记录目录由 root 拥有、权限 700，祖先目录不可由其他用户写入且无链接；清单和请求须为 root／600 的单链接普通文件，请求摘要与清单一致。原始文件允许保留原 UID／权限，但须为单链接普通文件、最多 128 KiB、UTF-8 且摘要匹配，才能生成恢复依据。符号链接、硬链接、无效清单和不完整记录不得用于恢复。

列表按目录修改时间倒序，每页 100 项；完整 JSON 版本、固定根路径、页码、数量和编号均核对后才更新。根目录最多收集合规编号的 100,000 项；每项服务查询最多 2 秒，整个服务器查询最多 30 秒，SSH 读取最多 45 秒。查询过慢时失败并保留原快照，不将部分数据当作完整结果。新增或变化的目录可能使翻页位置移动，各记录状态也不是跨服务器原子快照。

容量为各合规记录目录及其中单链接普通文件的 `st_blocks × 512` 合计，覆盖原始文件、候选、执行器和日志；不包含共享锁目录、根目录本身及其他路径。链接、嵌套目录、无法读取或无法识别的条目会标记统计不完整，此时只表示已量到的占用，不推算精确总量。读取不删除或压缩文件；任务目录容量、清理预览及独立审核清理入口可从 Tasks 的 Record storage 使用。

详情显示原服务器、已保存阶段及时间、当前到记录原始文件的差异、摘要、保存的检查设置、阶段事件和四类私有日志末尾（每类最多 8 KiB，合计四类）。日志及差异在解析后脱敏，结构字段与恢复设置不经凭据字面量替换。当前文件缺失仍可进入恢复审核；链接、非文本、过大或不安全路径不能生成可用比较。阶段代表过去保存的检查，不重新证明当前应用健康。读取结果只存页面内存，不补写本地任务历史或备份成功确认。

只有可验证的原始发布记录、无活动源任务、当前可比较且读取成功时才启用恢复。恢复记录本身不作为新的原始发布来源。点击恢复仅打开原服务器的统一任务表单，重新认证、预检查和审核，再由服务器保存当前状态并执行；服务状态无法核验或停止中，服务器预检查同样拒绝。恢复的是选定发布前保存的原始文件，不直接把冻结候选当成所选版本。自定义命令将随设置重新审核，读取阶段不会运行它们。

列表和同一记录详情刷新失败会保留旧内容及其采样时间；配置详情失败后禁用恢复，只有再次核验成功才能继续。重新连接时，仅保留地址、账户、配置编号及主机指纹全部一致的列表快照，读取失败会明确标识旧快照；更换身份不继承旧列表。普通任务日志与配置详情均不跨重连保留。离开 Configurations、查看最近变更、主动忘记或提交新任务时清除缓存凭据并丢弃私有详情；在途查询可能完成后才断开，其晚到事件被忽略。没有自动轮询、客户端调度器或自动清理。

### 记录存储与清理预览

Tasks 的第三个视图 Record storage 提供账户任务和 root 配置记录两种范围，Configurations 的服务器恢复记录页也可进入。独立选择最多 32 个已信任账户；配置范围按端点去重，任务范围允许同一端点的不同账户。每次连接核对原地址、用户名及指纹，先在 SSH 原账户中读取 UID／HOME，再通过 root／sudo 运行固定的只读程序，后续查询重新核对账户与根目录。需要 Python 3.8+ 及标准库 zlib，不使用 SFTP，不安装常驻进程。普通 Server records 的无 sudo 浏览方式继续保留。

程序以目录描述符和 O_NOFOLLOW 逐段打开任务根目录及直接子项，要求根及记录目录 owner／700 与原 UID 匹配；配置目录继续要求 root／700 及不可由其他用户写入的祖先。跨文件系统记录、链接、多重硬链接、嵌套或未识别文件等不作为清理候选；不递归遍历应用数据目录。配置 original／candidate 允许保留其原 UID，其他必要私有元数据要求 root。已分配字节统计目录和可计量普通文件的块数，逻辑字节另列，稀疏文件不会按逻辑长度估算释放量；排除内容明确标记统计不完整，共享配置锁不计入。已分配字节也不保证等于未来实际释放量。

保留参数默认为至少 7 天、最新 10 个账户任务或每个配置目标路径 3 份可验证的原始备份。配置至少保留一份；时间可设为 0–3650 天，数量 0–1000（配置下限 1）。任务年龄包含服务器元数据创建时间及文件修改时间。只允许确认退出且已停止的任务成为候选，失败服务与成功结果矛盾、遗留／损坏元数据、缺失证据及未完成配置阶段均保留。任务元数据不作为 root 配置引用的权威：即使声明为普通脚本，同编号私有配置记录或 restore_from 引用仍保护该任务。

引用核验读取并验证服务器私有清单与原始请求，收集来源关系，并保留各路径最新的可验证原始备份。损坏、缺失来源、不可读或无法解释的登记信息使引用不完整；此时仍可展示可测量的任务占用，但所有候选受保护，不把读取失败当作空登记库。已被引用的来源即使与引用者同时选中也保留，不自动推导删除顺序。候选配置还核对冻结候选及原始备份摘要；读取不会执行其保存的验证、重载或健康命令。

列表每页 100 条，跨页最多选择 100 条生成精确预览；支持选择本页候选和清除选择。预览列出文件及目录路径、占用、保护原因和采样时间，并在协议中保存目录／文件身份及引用快照指纹，供执行器重新核对。版本、范围、UID／HOME、根路径、策略、记录编号、精确对象边界及汇总值均匹配后才接收结果；候选不能包含未知文件、越界路径或遗漏的必要证据。预览协议只有 preview_only=true 的只读语义，不写任务历史或备份成功确认；页面的清理审核入口转入另一套明确提交的服务器任务流程。

每次查询最多处理 10,000 个登记／记录和每个目录 64 个直接条目，最多返回 2 MiB；超过限制失败或将目录标为受保护，不声称完成递归计量。服务检查最多 2 秒，服务器总体 30 秒，SSH 读取 45 秒。独立于普通读取错误的 BaseException 超时可穿透逐条容错，避免计时信号被 OSError 捕获后继续扫描；普通配置记录读取也采用相同方式。

固定程序与 JSON 参数通过 zlib／base64 压缩后在服务器内存中解码。libssh2 的发送控制包存在大小限制，生成的最终命令限制为 32 KiB；参数不会借用 sudo stdin，解释器入口仍关闭 stdin，避免未消费口令成为程序输入。传输压缩不省略检查、记录或对象，也不压缩服务器文件。

结果为按需、非跨服务器原子快照。刷新失败保留上次结果；选择变化或成功刷新列表会丢弃旧预览。离开 Tasks、切换视图、提交新任务或主动忘记会清除凭据、选中集和预览，在途读取可能稍后结束，其晚到事件不更新视图。列表仅在身份与策略一致时可跨重连保留。预览不能直接作为删除授权；实际执行流程如下。

### 服务器记录清理

审核入口仅收集当前无查询错误、凭据未忘记、有可清理候选的预览，排除其中受保护行，并绑定原配置编号、端点、SSH 账户和主机指纹。统一任务表单只列出这些服务器，重新填写凭据；不复用存储查询口令，不允许把文件计划应用到新端点。每台服务器最多 100 个候选，完整文件审核文本最多 128 KiB，JSON 计划最多 2 MiB。清理不是普通脚本参数展开，不能通过编辑展示文本改变目标。

预检查在原 SSH 账户中通过独立 stdin 上传私有 JSON，随后才用另一个 SSH 命令调用 sudo；原账户 UID／HOME 必须匹配。root 引导程序来自固定客户端代码，读取上传文件时逐段拒绝链接，检查 owner、权限、单链接、大小和摘要；不会运行上传的执行器。重新生成精确预览并比对引用、根和每个文件身份后，将计划、可信程序和初始报告冻结于 `/var/lib/arcnix/record-cleanups/<任务编号>/`（root／700，文件 600）。成功后原账户尽力移除自己的上传文件；失败上传或失败预检查可能留下账户 staging，清理不递归处理这些目录。预检查不删除候选。

用户审核每台服务器的完整文件清单后，才显式执行。原有 systemd 启动器提供操作锁；Python 执行器验证并复用继承的同一锁描述符，也支持独立调用时加锁。执行器再持有配置登记的独占锁和所选配置目标路径锁，重新生成候选并核对冻结依据。配置预检查持登记共享锁；原有路径锁还可协调旧的配置预检查执行器。登记缺失与确实为空使用一致的空集指纹，权限或解析失败仍保持不可核验，不能借此绕过保护。

每个选中记录通过 Linux `renameat2(RENAME_NOREPLACE)` 移入同一记录根目录下专属的 `.arcnix-cleanup-<任务编号>` 私有暂存区，核对移动后的 inode 并冻结为 root／700。目录冻结后再次比对精确子项及文件 token；只使用目录描述符逐个 unlink 预览中的单链接普通文件，不跟随链接、不递归遍历或删除未知文件。原始备份最后移除；目录及暂存区仅在空且身份仍匹配时移除。每步保存 intent／已删除文件并 fsync，在任务日志发出阶段标记。报告和冻结计划继续保留，不在当前任务／配置容量及清理范围内。

执行前文件变化、活动任务、新的恢复引用或锁冲突会拒绝删除。开始移除前若核验失败，尽力归还同一记录并恢复目录 owner／权限，禁止覆盖新出现的同名目录。移除已开始或归还失败时保留私有暂存区，在报告中标注失败／中断；不能保证恢复被删文件。SIGTERM／SIGINT 可保存中断报告；SIGKILL 或服务器故障可能只保留最后一次已落盘 intent，必须结合实际服务和文件核查。已有暂存残留阻止同一范围继续清理；同一清理记录仅能从 prepared 开始一次，失败或中断不能重放。当前没有自动续跑、通用撤销、服务器重启恢复或暂存区的图形化人工恢复；这些需要后续单独设计。

已接收任务由服务器完成，客户端只观察进度；关闭客户端不影响删除和报告。多个服务器各自成功或失败，不承诺跨服务器原子清理。查询原任务无需重新提交；本地历史只保存任务身份、审核路径及有界输出，不保存冻结请求、程序摘要、凭据或任务自由标题。

### 清理报告与残留核查

Tasks 的第四个视图 Cleanup reports 使用独立服务器选择、SSH／sudo 认证和按需查询，不依赖活动工作区或本地批次。列表每页 100 条，最多扫描 10,000 个审计目录；占用仅统计私有审计目录及可测量普通文件，不包括账户任务树、暂存区或整个服务器。无效／链接目录保留问题提示；不完整计量不会宣称精确总量。

固定读取程序由配置／存储只读 helper 和 `cleanup_records.py` 组成，压缩命令限制 32 KiB；不载入清理执行器，不运行服务器保存的 runner，不读取任务输出或原始配置正文。私有审计根固定为 `/var/lib/arcnix/record-cleanups`，目录要求 root／700、安全祖先，JSON 要求 root／600、单链接普通文件且不超过 2 MiB。全部查询受 30 秒全局超时、2 MiB 响应和 45 秒 SSH 限时保护；超时异常不会被逐条容错吸收。

列表展示保存阶段、最近时间、已处理记录、已标记删除文件和当下 systemd 状态。活动／停止中优先显示，completed 报告与 failed 服务显式标明矛盾；prepared、running 的旧阶段不会在重连后自动当作成功。详情将冻结请求、报告来源和所选编号相互核对；新报告还校验请求摘要。原记录根必须与原 scope／UID／HOME 对应并匹配冻结根身份，暂存路径只能为该根下的确定编号，不接受报告指定任意目录。

详情只用目录描述符及不跟随链接的 stat 检查每个原位置和暂存位置。文件状态区分与审核一致、后来变化、缺失、不安全及无法判断；保存的 removed／pending 标记另列。pending 对应当前缺失的文件只表示最后一次 intent 尚未确认，不因此捏造已删除记录。未知文件或不合规结构使残留检查不完整，不向其内部递归。

新执行器在 rename 前持久保存原目录 dev／inode、owner、权限、链接数、大小及时间，数组摘要必须匹配冻结目录 token，暂存目录还须保留同一 dev／inode 且为 root／700，才能标为身份已证明。旧报告没有数组时仍可查看安全元数据，但身份保持未证明，不能作为自动恢复依据。目录证明、请求和报告标识均不等于处置授权；残留导出或移除另行重新认证、核验、审核及提交，见下文。

读取期间报告或请求文件变化会拒绝更新，用户可重新查询；失败保留相同身份的旧快照和采样时间。重连只继承配置编号、端点、账户及指纹均一致的列表，私有详情不跨认证复用。离开 Tasks、切换子视图、提交新任务或忘记凭据后清除认证与详情，晚到事件按 serial 拒绝；在途读取可能稍后才结束。自由错误文本按当前 SSH／sudo 凭据脱敏，结构路径保持原值。读取事件在持久历史处理前返回，不补写任务结果、备份成功确认或本地报告文件。查询没有自动轮询、服务重启、任务续跑或审计记录删除行为；残留导出／移除使用下面独立的变更流程。

### 残留导出与核验移除

`record_recovery.rs`／`.py` 为清理报告增加两种类型化任务。来源必须为 failed／interrupted 或遗留 running 且服务已停止的清理；冻结根、报告、请求、暂存区及每个残留文件身份都要重新核验，目录同 inode 证明不可缺失。原位置重新出现同名目录、未知项、链接、不安全文件或来源仍活动时拒绝。读取报告不授予执行权限，两个入口各自重新认证并固定原端点和主机指纹；执行管理员可以不同于原清理账户。

预检查将请求与固定客户端程序经原 SSH 账户上传到 `.local/state/arcnix/recovery-staging/<任务编号>`。专用上传最多 4 MiB，命令最多 32 KiB，边发送边读取输出以处理双向 SSH 窗口；不完整输入失败，普通 `exec_stream` 输入仍限制 4096 字节。上传程序最多 256 KiB、请求最多 2 MiB，文件均为账户私有单链接普通文件。sudo 只接收口令，固定的提权引导程序逐段拒绝链接并核对当前 actor UID、700／600 权限和两份 SHA-256，然后才编译固定客户端程序，不执行未经摘要核验的上传内容。无需 SFTP。

服务器以 root／700 在 `/var/lib/arcnix/record-recoveries/<任务编号>` 冻结计划、程序、报告，并在原清理审计目录登记指针；每个原清理最多 100 条处置记录。预检查限时 30 秒，不复制或删除数据。显式提交后由 systemd 持有执行过程和操作锁，最长 24 小时；配置暂存移除还持有配置登记独占锁。客户端退出不停止任务，不提供自动续跑或通用服务器重启恢复。

导出在新建 `files/<原记录编号>/<文件名>` 内复制剩余字节，文件保持 root／600；原 uid、gid、mode、mtime／ctime 纳秒及最多 128 项／128 KiB 扩展属性编码到 `metadata-<文件名>.json`，不将原权限或 ACL 应用到副本。按文件保存源／副本 token、字节 SHA-256 和元数据 SHA-256。支持稀疏零段，读取与完成前复验来源；不修改源暂存区、不恢复已删除文件，也不覆盖业务原路径。

移除需要用户选择本来源已完成且停止的导出，冻结清单的身份和摘要。运行时先遍历校验导出全部数据及元数据的 SHA-256，再复验当前源快照；只 unlink 本次审核的仍存在源文件，最后移除身份相同的空目录及暂存区。保存每项 pending／removed 并 fsync，不递归删除，不删除导出副本。SIGTERM／SIGINT 中断保留部分结果；同一任务只可从 prepared 执行一次。新任务可以在重新核查后处理已导出文件的剩余子集，但不会跳过对导出全部文件的校验。

清理报告只读详情会列出关联导出／移除的阶段、实际服务、数量和目标目录；完成导出单独选择后才开启移除审核。导航、关闭详情、忘记凭据和重新认证撤销选择与私有详情，失败保留旧快照但禁用操作。处置任务历史只保存任务身份和有界结果，不保存冻结来源、凭据或程序摘要。完成导出可直接下载为本地 ZIP，见下文；业务原路径恢复及导出副本删除执行器仍未提供。清理审计的独立审核移除见下文。不承诺应对任意 root 写入者、硬件故障或跨服务器原子处置。

### 残留导出的本地下载

清理报告的关联导出及独立残留导出库存提供下载入口，使用该页的固定原端点、账户、主机指纹与临时管理员访问，不要求工作区连接或 SFTP。`export_download.rs`／`.py` 在固定 `/var/lib/arcnix/record-recoveries/<编号>` 内只读检查已完成且停止的导出，核对冻结请求、报告、清单、精确条目及数据／元数据身份。清理来源的暂存区已移除也可以读取既有导出；不运行被冻结的 runner，不再次执行导出任务。

独立清单最多 100 个原目录、900 个数据文件、2 MiB 响应；数据必须与原审核对象成对对应，元数据文件最多 256 KiB，三份审计 JSON 各最多 2 MiB。下载只发送紧凑的冻结身份及库存摘要，精确文件列表留在只读界面，不扩展普通 stdin 4096 字节限额。服务器重新匹配快照，逐文件读取并核对 SHA-256、长度、前后身份及最终库存／停止状态后才返回单一最终回执。

ZIP 包含 request.json、report.json、manifest.json，以及 files/ 内的数据、原始元数据 sidecar 和空目录；使用 ZIP_STORED、固定容器时间和 ZIP64 流式写入，不创建服务器临时压缩包。原时间、uid／gid、mode、扩展属性保留在 sidecar，不自动解压、恢复业务路径或应用原权限，ZIP 不保留稀疏布局。不可寻址输出和 ZIP64 写入依据 [Python zipfile 文档](https://docs.python.org/3/library/zipfile.html#zipfile.ZipFile.open)。服务器读任务有限时 1 小时，不增加常驻服务或周期调度；本地传输期间客户端需要打开，服务器原副本完整性不依赖传输连接。

SSH 使用可取消的增量读取，不保留 ZIP stdout 文本尾部；本地逐块校验并写入新建 .partial 文件。成功必须同时匹配精确请求摘要、清单摘要、完整 ZIP 长度／SHA-256、条目数及正常退出；然后 fsync、关闭文件并复用 `local::rename` 不覆盖发布，拒绝同名目标。Windows 使用不带替换标志的 [MoveFileExW](https://learn.microsoft.com/en-us/windows/win32/api/winbase/nf-winbase-movefileexw)，不要求目标盘支持硬链接；其他平台沿用本地文件的不覆盖硬链接发布。失败／正常取消移除暂存文件，关闭弹窗、忘记访问或离开页面取消传输并拒绝迟到结果。强制进程退出可能留下明确命名的 .partial 文件，最终 ZIP 不会因此被标为完成；可以重新认证后重新下载。配置与任务历史不记录访问口令、冻结清单或下载会话；用户选择保存的 ZIP 包含上述审计依据。

### 审计与导出存储预览

任务中心的清理报告提供独立的审计／导出存储视图，复用原服务器选择、固定端点、主机信任及临时管理员访问，不要求单机工作区连接或 SFTP。三种范围固定为 `/var/lib/arcnix/record-cleanups`、`/var/lib/arcnix/record-recoveries` 及 `/var/lib/arcnix/audit-cleanups`（审计清理结果），不接受任意根路径。`audit_storage.rs`／`.py` 通过私有读取器按需执行；库存和预览不运行保存的程序、不删除文件或停止服务，也不设置维护计划。

库存每页 100 条，最多检查 10,000 条目录项；全次最多计量 50,000 个子对象、最多三层目录，响应最多 2 MiB。区分逻辑文件字节与目录／文件实际分配块；链接、非普通文件、不安全权限、变化或超出计量上限保留不完整标志，不能把部分和当成完整容量。服务器读取期限 30 秒，SSH 期限 45 秒；大目录超时须缩小或另行管理，客户端不驻留采集。

保留条件默认 30 天／最近 20 条，允许 0–3650 天与 1–1000 条；数值只用于下一次读取和预览，不写入服务器计划。可跨页选择最多 100 条，再重新扫描得到精确候选对象与保护原因。只有已完成、停止且无残留、未被引用、结构完整并超出保留条件的清理审计记录可列为候选；failed、活动或未知服务、未完成报告、损坏请求、原位置／暂存区仍存在，以及不完整引用检查均受到保护。导出数据及其关联处置证据保留，不通过该视图删除副本或移除来源指针。

引用索引从 root 持有的导出／移除请求和报告建立；清理报告受来源引用保护，恢复记录与清理指针一起保留。扫描前后检查根、引用文件、目录项及对象身份，变化时保守保护。响应包含可选根身份与引用摘要；旧读取仍可显示，但缺少这些证明的预览不能进入清理审核。候选预览只列出 `request.json`、`report.json`、`runner.py` 和对应目录；它不是执行授权，也不能传入原账户任务清理器。

客户端校验范围、策略、分页／所选编号顺序、对象封闭路径、身份、容量和候选总数。失败保留原快照；策略在读取期间变化时丢弃旧策略预览。离开 Tasks、忘记凭据或切换视图清除私有对象与选择；过期查询不能重新填入它们。库存和预览不写入本地任务历史或配置；用户另行审核后产生的任务正常保存批次、目标、文件审核摘要和有界结果，完整冻结请求与对象身份留在服务器。`tools/audit_storage_smoke.py` 覆盖真实桌面与回环响应，`audit_storage_integration` 是显式启用的真实 Linux 文件系统／systemd 测试；测试在私有 mount namespace 中挂载独立库，不访问线上审计数据。

### 独立审核的审计清理

`audit_cleanup.rs`／`.py` 只接受清理审计范围的完整候选，过滤所选项中的保护记录；导出副本与审计清理结果不可进入该执行器。模板固定原服务器编号、账户／端点和信任指纹，进入单独表单重新认证，预检查及执行再次核验。清理前重新读取原对象、服务、保留条件、原位置／暂存区和引用；过期文件、根或引用摘要不再匹配时停止，不自动重试。

`private_program.rs` 共用残留处置与审计清理的私有上传流程：原账户通过专用有界 SSH 上传发送固定客户端程序和请求，独立于 sudo 口令；提权入口逐段拒绝目录链接，验证 actor UID、700／600 权限、普通单链接文件及两份 SHA-256，再编译固定程序。程序最多 256 KiB、请求最多 2 MiB、整帧最多 4 MiB；仅三种固定 staging 命令可使用扩展上传，普通命令 stdin 限额不变。审计准备回执另行核对原请求摘要、任务编号和候选数量。

预检查冻结 `/var/lib/arcnix/audit-cleanups/<任务编号>` 内的请求、程序与 prepared 报告，只检查同文件系统隔离条件，不移动来源。显式提交后由 root systemd 任务执行，复用服务器操作锁及 `cleanup_exact_records` 精确文件引擎。新的审计登记锁与当前清理准备、残留处置准备互斥，避免检查与登记引用交错；旧冻结程序仍保持原版本，不借客户端升级重写。

实际执行重新扫描后，将每个审核目录无覆盖移动到该任务私有 `quarantine/<来源编号>`。验证仍为原 inode，核对完整条目及各文件身份，删除前持久记录 pending，删除后 fsync 并记录 removed，再移除同一空目录。只操作审核文件，不递归删除。未发生 unlink 时尽量放回原目录；已经部分移除则保留余项、隔离区和私有报告，不自动恢复、续跑或重放。审计清理结果视图可独立发现这些记录并同时显示保存阶段和实际服务状态；原任务／独立账户记录保留有界日志，日志提供私有报告路径。

新的清理程序在进入失败补偿／报告阶段前屏蔽 TERM、INT 和 ALRM，防止后续停止信号再次打断收尾。该保护只覆盖新冻结程序的短收尾，不承诺强制终止、重启或存储故障下完整写入；SIGKILL 仍可终止进程，实际服务状态和 pending／残留仍需重新核查。行为依据见 [Python signal](https://docs.python.org/3/library/signal.html#signal.pthread_sigmask) 与 [systemd.kill](https://www.freedesktop.org/software/systemd/man/latest/systemd.kill.html)。

执行器的软期限为 180 秒；这不等于底层存储故障的硬终止保证。`audit_cleanup_integration` 使用私有挂载与有限 systemd unit 验证真实移除、变更／引用拒绝、不可重放和多次 SIGTERM 部分结果；只在测试进程以本地 C interposer 延迟 unlinkat，生产程序保持原字节。测试清理确认 unit 无活动状态且 cgroup 无进程后才移除私有根。导出副本、来源指针及审计清理依据的后续保留和明确范围的人工恢复仍需另行完善。

`audit_details` 为审计清理结果提供独立的只读详情。读取固定 root 私有目录中的请求和报告，核对原请求摘要、目标及目录证明；冻结的 runner 不读取、导入或执行。每个来源固定列出 request.json、report.json、runner.py，分别提供报告的 removed／pending／未记录，以及原位置和暂存位置当前的 matching／changed／absent／unsafe／unavailable 元数据。没有删除确认的缺失文件仍显示待确认或未记录，不推断执行成功；保存阶段与实际服务状态分开显示。暂存目录身份依赖移动前证明及实际 inode，不能仅因路径相同认定为原目录。

查询限时 30 秒，响应限 2 MiB、100 个来源，每个来源目录最多检查 64 项，不递归扫描；前后核对文件、目录映射、根及服务状态，变化给出不稳定快照，读取错误保留先前结果。界面按服务器独立打开／刷新／关闭；关闭中的结果、忘记凭据、切换范围或离开页面后，迟到事件不能重新展示详情。读取不创建本地任务历史，不重放清理；解释置于 `?`，文件状态位于有界可选文本中，正文沿用现有统一字号。

## 安装模板与服务器检查

installers.rs 和固定 installers.sh 定义安装检查；执行器自身不需要 Python，Python 3 安装模板可用于准备后续配置／快照工具。新 Definition v2 包含版本、枚举类型、精确包名和明确的安装策略，官方定义由目录创建，普通软件入口仅创建包检查；自定义脚本或复制模板不继承类型化安装能力。脚本中心按当前库判断来源，列表键包含来源及版本，不以用户可控的编号前缀认定官方。模板指纹覆盖定义、固定执行器、守卫和探针命令；各目标另生成审核摘要，约束实际包版本、架构及动作，不固定软件归档内容或应用行为。v1 定义只用于读取旧报告，新提交必须使用 v2 和新的目标预检查。

预检查读取 OS ID、版本、原生 dpkg 架构，并逐条查询请求包；同时在服务器对完整 dpkg 状态做有界摘要，不使用最多 1000 项的界面列表推断缺失。APT 精确包校验及禁止移除的模拟继续保留。缺少适用环境或 timeout、base64、mktemp 等基础工具时不提供就绪目标；审核展示已有版本／状态、APT 计划、实际命令、检查范围及失败影响，不显示编码后的完整执行器。完整引用后的 systemd 载荷上限也在预检查核验。

实际任务在服务器重新核对 OS ID／版本／架构及安装前状态，再按审核过的策略执行带 dpkg 前置守卫的非交互 APT 命令。每个请求包都验证 dpkg 安装状态（包括已保持的安装，拒绝 rc／iiR 等状态），官方模板追加固定检查：Python 3.8+、Git／restic 版本、诊断程序、数据库客户端程序，以及 Nginx 可执行程序、配置和 active 服务。Nginx 不检查 HTTP 或外部可达性；数据库客户端不证明数据库访问或权限；restic 程序检查不证明仓库可用。独立只读探针在 APT 失败后仍尝试收集部分状态，不自动卸载、重试或回滚。

探针每项限时 20 秒，额外 2 秒终止宽限，文件输出有 ulimit 限制；详情最多 512 字节，超限或超时为未知，并保留原因。完整逐项报告在末尾重新输出，最多 32 KiB，可从 48 KiB 服务器日志尾重新读取；格式核对原任务编号、模板版本、定义、步骤顺序、数量及最终结果。信号中断尽力保存已确认步骤并将未完成项标为未知；强制终止或记录不完整时不推断成功。临时检查文件位于服务器私有临时目录，正常结束只移除已知文件和空目录；任务记录仍只有 output、result 和 record.json，不改变清理白名单。

任务历史兼容旧数据，并为新安装保存定义。任务中心和独立服务器记录展示可读检查，原始协议保留在服务器完整日志，不用于授权任何后续操作；服务器任务状态未确认或与报告不一致时，已保存检查不升级为已确认成功。普通 Shell、服务变更及索引更新保持各自流程。客户端关闭后由现有 systemd 任务继续，缺失提交确认仍先查询原任务；不新增定时计划、桌面常驻、跨服务器串行编排或通用服务器重启续跑。
安装报告沿用结构化日志脱敏：解码自由详情后替换本次凭据，保留已校验的公共状态、编号和版本字段；脱敏后重新限制 UTF-8 长度。口令与状态词或数字重合不破坏完整报告。类型化安装退出 0 而证明不完整时，本地任务仍为未知；加载持久历史及重连查询均执行该核验。

### 安装策略与变更核验

全局运行表单默认“仅安装缺失的软件包”。APT 命令使用 --no-upgrade 保护请求包，审核解析另外拒绝修改已有依赖或配置已有包；明确选择“允许审核过的升级”后重新预检查，可审核升级及已有未配置包的配置动作，仍拒绝移除和降级。候选版本依照服务器当时的软件源和配置；没有安装请求变更时，只运行检查，不调用写操作 APT，也不改变自动／手动安装标记。

`installation_review.sh` 在同一管理员上下文中读取完整 dpkg 状态摘要、请求包逐项状态与 APT 模拟，前后摘要必须一致。状态读取限 16 MiB／20 秒，模拟限 45 秒、额外 2 秒终止宽限及 128 KiB 输出；输出通过私有 FIFO／head 有界捕获，不把小文件上限施加到 APT 的正常缓存写入。完整响应限 128 KiB，最多 512 个动作；版本限 128 字节。模拟明确给出 Inst／Conf、版本和目标架构，未知格式、缺失请求、重复动作及移除提前拒绝，降级通过服务器原生 dpkg 版本比较拒绝。每个安装动作需要匹配配置动作；审核摘要按规范动作排序，包含所有依赖的安装／配置版本与架构，不受展示顺序影响。

提交载荷携带 dpkg 状态摘要、规范动作摘要及数量。`installation_guard.sh` 通过 APT Pre-Install-Pkgs 协议 3，在 APT 持有前端锁、调用 dpkg 之前校验实际动作；不以再次模拟作为原子保护。守卫限时 60 秒、额外 2 秒终止宽限，输入最多 512 KiB；拒绝未知协议、未确认的前端锁、移除／降级、策略不符及摘要／数量变化。此时下载可能已经发生，已有 APT 钩子也可能运行；不是无副作用模拟或通用回滚。核验成功产生私有印记，APT 返回后独立保存 plan／install 结果；缺少印记即使 APT 返回 0 也不能成功。包与应用检查继续独立收集，缺少最终完整报告仍保持未知。新报告显示策略，旧报告保留观察并提示未记录审核变更证明。

任务启动层只在交给 systemd 的 ExecStart 边界把 `$` 转义成 `$$`，防止 service manager 提前展开 Shell 代码或字面参数中的 `${...}`；之后 Shell 获得原始文本，参数仍按原有规则引用。该修复适用于全部服务器任务，不引入新执行器；真实 systemd 检查覆盖 Shell 参数展开、带美元符号的字面量、PID、awk 字段以及原用户和 root 工作负载。旧任务不自动重放或补写证明。

机制依据为 [APT 模拟与 --no-upgrade](https://manpages.debian.org/trixie/apt/apt-get.8.en.html)、[APT 调用 dpkg 的钩子协议](https://manpages.debian.org/trixie/apt/apt.conf.5.en.html#HOW_APT_CALLS_DPKG(1)) 和 [systemd-run 环境展开](https://www.freedesktop.org/software/systemd/man/latest/systemd-run.html)。当前原生验收环境为 Ubuntu 24.04 amd64、APT 2.8.4 与 systemd；其他发行版／架构仍需单独验收，不据此宣称已覆盖全部 Debian／Ubuntu 版本。

## 按需恢复演练

新演练在提交前把执行服务器编号及公开的 Description 写入服务器 `record.json`，成功写入后才启动 systemd 工作负载。该请求不含认证文件引用、脚本或数据库密码；服务器记录与记录存储读取的元数据上限为 8 KiB，Description 仍限制 4 KiB。新增字段为可选项，旧记录无需迁移。请求本身不代表服务器已经接收、执行过恢复或通过验收。

本地历史丢失、日志末尾不含最终报告或服务被 SIGKILL 后，独立任务记录仍可展示原快照、来源、执行服务器、新目标和验收条件。报告读取绑定新记录中的执行服务器与 Description，错范围或错服务器的退出 0 不能显示验收成功。界面把该兜底内容标为“请求；尚无执行证明”，查看不会续跑或生成成功确认；旧记录没有请求时继续只显示可核验的原日志。此功能不保存逐阶段检查点，也不承诺 SIGKILL 或重启产生最终报告。

Backups 的目录／PostgreSQL 快照提供 Run recovery drill，复用统一服务器任务和目标选择。目录演练恢复完整快照，PostgreSQL 演练恢复一个匹配导出路径的新库；原普通／选定文件恢复保持独立。每次定义 1–12 项必需验收，不接受自由 Shell 或 SQL。表单使用稳定行编号维护字段，删除不会串值；关闭、导航及切换上下文清除临时检查和浏览访问。

recovery_drills.rs 构造类型化 Job 和最大 4 KiB 的 Description，版本指纹覆盖说明、固定 Python 程序及实际恢复／预检查命令。只有模板工厂设置 drill 能力，普通用户脚本不能凭编号获得能力。目标仍须在原策略范围，源快照和执行服务器分别记录。固定程序压缩、请求 Base64 编码后经 SSH 提交，执行载荷最多 32 KiB，完整 sudo／systemd 引用后最多 64 KiB；在显示 Ready 前核验，不经 SFTP。

预检查先验证 Python 3.8+、现有可写的真实父目录／数据库暂存目录，再复用原恢复检查。执行时再次核对完整快照 ID、策略／来源标签、路径和 PostgreSQL 导出类型。目录目标不得覆盖已有对象或与当前源、原快照路径及本地仓库重叠；数据库须为新名且不存在。元数据的 stdout 与诊断 stderr 分别读取，防止工具警告污染 JSON。各条命令和恢复过程均在服务器，由 systemd 持有；实际运行并发与提交并发仍不同。

文件验收按目录描述符逐级拒绝链接，先检查类型，再以非阻塞只读方式打开普通文件，核对大小及可选 SHA-256；摘要最多 120 秒，前后文件身份、大小和时间变化保留未知。管道、设备及链接不作为普通文件读入。PostgreSQL 对普通／分区表做只读统计，固定 pg_catalog 搜索路径及目录／聚合引用，语句限时 30 秒、子进程限时 45 秒，并设置 row_security=off，避免行过滤导致不完整计数。角色权限不足、过滤影响、视图／直接外表及未达到阈值不通过；不启动应用，也不验证全部业务数据、角色、授权、扩展或外部依赖。相关服务端语义见 PostgreSQL 的 [连接默认参数](https://www.postgresql.org/docs/current/runtime-config-client.html#RUNTIME-CONFIG-CLIENT-STATEMENT) 和 [libpq 环境变量](https://www.postgresql.org/docs/current/libpq-envars.html)。

固定程序总时限为 24 小时。子进程使用独立进程组，同时继承服务器操作锁描述符 9；终止时处理进程组，包括原始子进程已经退出但仍有后代的情况。客户端关闭不影响已接收任务；信号处理尽力输出中断结果，强制终止、主机重启或报告缺失时保留未知，不自动续跑或重试。恢复数据始终留在新目录／新库中，临时数据库归档沿用原恢复的清理逻辑。

完整报告最多 32 KiB，详情最多 512 字节，记录服务器时间、耗时、工具版本、精确范围及每项状态，保存在原 output 日志，不增加任务目录文件或修改清理白名单。记录字段校验任务、版本、执行服务器、范围、顺序、数量及退出结果；对自由详情解码脱敏并再次限长。Task 的可选 drill 兼容旧历史；退出 0 仍必须有完整匹配的必需检查，历史加载及重连同样核验。独立服务器记录新增 Recovery drill 类型，读取不会重复执行或补写成功确认。

备份确认增加独立 RecoveryDrill 分类；核心观察器也核验报告，防止只凭退出 0 写成功。索引仅保存检查数量及演练版本，完整定义位于最近任务和服务器报告，避免扩大 4 MiB 主配置。失败或未知保留原先成功快照、目标、范围与时间。报告随原任务记录保留／清理，不承诺已删除日志可恢复；旧任务仍按原语义读取。

当前可对同一可访问快照选择多个策略内服务器分别演练；各目标必须直接访问原仓库和快照。尚未提供来源服务器离线时独立指定来源标签的异机恢复向导、MySQL 数据库演练、定时计划、跨服务器串行编排或应用自动接管；真实 SSH＋sudo、发行版、架构及远程仓库矩阵仍需扩展。

## 真实 SSH／sudo 配置验收夹具

`tools/native_ssh_fixture.py` 在 WSL Ubuntu 的私有 mount namespace 内运行解包的 OpenSSH；公开账户映射、测试 shadow 与 sudoers、SSH 私有 home、密钥及 sudo 时间戳均为临时副本。不会安装 SSH 服务、修改宿主密码或授予全局免密权限。临时服务有 600 秒上限，退出时只清理本次登记且路径匹配的任务、应用服务和记录，并核对宿主认证文件摘要。包来源和摘要见 `artifacts/ssh-native-tools/provenance.json`。

原验收通过实际桌面预检查、SFTP 上传、OpenSSH 公钥认证和 PAM 密码 sudo 发布 root 所有的文件；使用绝对路径的 Nginx 自定义校验／重载及 HTTP 健康检查，不等同于验证内置 Nginx 的所有 PATH、发行版或架构配置。客户端退出后等待原服务器任务完成，再重连查询；不启动客户端后台执行器。

## 任务结果观测与停止中状态

最近批次的实时观察和手动查询使用 `remote_tasks::Observation`。按需读取退出结果前后分别查询 systemd 的 `LoadState`、`ActiveState` 与 `InvocationID`；运行／停止状态优先于保存的退出码。已结束状态和调用身份一致时才确认退出结果，服务失败与保存的 0 冲突、服务状态不可用、查询期间发生变化或结果缺失时保留未知。状态变化可继续只读观察，永久未知结束本次进度查看；实际工作仍由服务器持有，不重复提交。

`Stopping` 是活动状态。重启后与运行中／提交中一样转为未知，清除未确认的退出码；配置恢复入口使用活动状态判定，覆盖停止中。安装／演练仍需原有完整报告，服务退出确认不会替代应用或数据检查。

`task_query.sh` 与独立账户记录读取复用 `task_exit.sh`。退出文件需要可读、普通、单链接且最多 4 字节，前后核对文件身份，再将原始字节编码传回；Rust 验证 0–255 的十进制及可选单个换行，避免 Shell 替换删除 NUL 或多余换行后误认成 0。独立记录行协议更新为 2，保存的 `record.json` 仍为原格式；旧元数据缺省的任务照常读取，不依赖服务端 Arcnix 升级。

最近查询限制为 10 秒、48 KiB 日志尾部和 64 KiB 整体响应，核对返回的任务编号；独立记录沿用分页和时限。读取不需要 Python、SFTP 或 sudo。服务属性含义依据 [systemd D-Bus API](https://www.freedesktop.org/software/systemd/man/latest/org.freedesktop.systemd1.html)，收尾检查使用 [ExecStopPost](https://www.freedesktop.org/software/systemd/man/latest/systemd.service.html#ExecStopPost=)。这些结果仍是查询时的快照，不补写旧任务证明或承诺服务器重启续跑。


## 最近批次的多目标结果查询

`task_refresh_ui` 单独保存本次读取的选择、凭据和并发，不复用脚本执行表单，也不进入持久模型。每次提交先完整核对所有选中目标的原地址／账户、当前信任指纹、远程目录及重复查询状态，再将请求交给 `batch_worker::refresh_many`。未提交、已改身份或正在查询的目标不可选择；取消选择、关闭表单和提交均清除表单凭据，工作请求持有的凭据使用 `Zeroizing`。

每批只启动 1–8 个有限查询线程，空闲线程领取下一目标，单台认证／协议失败不取消其他目标。单目标入口使用同一核对与读取逻辑。查询不获取管理员密码、不依赖 SFTP，不启动或恢复工作负载，也不安装后台程序。`Event::Refreshed` 仍复用原有结果观测和安装／演练证明检查；错误保留旧日志并清除未经确认的退出码。事件只按原批次和目标编号更新，不改变导航；关闭客户端不影响服务器持有的任务。

查询集合未清空时，更新安装的空闲判断不成立；手动重启和自动倒计时等待有限读取结束。查询结束后恢复原更新逻辑，不将结果读取变成后台监视。

回环验证：`python tools/batch_refresh_smoke.py`。夹具的 `trace-task-queries` 标志仅记录任务编号、查询开始／结束和测试时间，用于核对实际并发与未重复提交；不记录凭据。原配置发布专项另通过真实 SSH 核对查询前后结果文件身份和服务调用身份。

## 任务刷新与页面切换跟踪

所有页面赋值通过 `navigation::change_page`，统一离开页面的临时访问清理，保留进入工作区的行为；任务准备和更新通知也适用相同清理。debug 构建显式设置 `ARCNIX_TEST_TRACE_INPUT=1` 时，将固定页面名、来源、时间、序号及清理前后是否保留备份访问的布尔值写入测试进程 stderr；来源区分侧栏、普通操作、任务预检查、服务器选择和更新通知。正式构建不包含此跟踪，也不新增用户设置。

同一标志使 `Desktop` 夹具记录按钮点击／导航变化，以及测试调用 `Locator.click` 的开始／结束时间；后者只记录时间和序号，不记录参数或选择器。Windows WebView2 测试另外透明包装消息传输，仅记录激活事件的节点编号及对应输入序号。Wry 的 `window.ipc` 对象被冻结，夹具保留它，通过底层 WebView2 传输转发原消息，不更改参数或发送顺序。日志不记录表单值、普通字符键、IPC 消息正文或凭据。页面类变化去重，便于核对测试调用、DOM 输入、IPC 激活和 Rust 回调。

`python tools/task_navigation_smoke.py --rounds 64` 连续提交双目标任务，交替切换全局页面、输入并取消脚本草稿、切回已连接服务器、修改主题、查询批次和轮换最近十批。验证用户选择的页面保留、两台结果分别完成、原 SSH 工作区保留，以及侧栏输入与 native 回调逐项对应。该检查为已有偶发跳页保留诊断依据；没有复现时不能据此宣称问题已修复。

## 当前任务快照的读取时间

`tasks::Target::result_read_at` 是可选的客户端 UTC 秒值，缺省为空，旧历史不补造时间。独立 SSH worker 在成功校验原任务观测后封装 `batch_worker::Snapshot`，记录本机接收时刻，再交给 UI；UI 排队或绘制时间不改变它。有效观测即使状态为未知也可以有读取时间，不能据此确认任务成功。传输、认证、返回任务编号或协议检查失败时，保留旧日志及其原时间，继续清除未确认退出码。

实时观察仍按观测内容去重，不为时间字段新增心跳消息或写盘；重复相同观测不替换当前显示快照的时间。手动单目标和批次查询成功时正常替换。时间经过现有绝对日期／时区格式展示，`?` 说明它采用客户端时钟、与任务完成时间不同，也不代表持续确认状态。重启保留原时间，活动状态仍按原规则变为未知；备份／安装／演练结果门槛及服务器协议不变。

`python tools/task_read_time_smoke.py` 覆盖双目标实时观察、内容不变的去重、未知状态快照、认证／协议／任务编号失败、旧历史、手动查询、重启持久化和中文窄页帮助。

## 计划目录与提交边界

预检查成功后会记录计划中的任务目录，所以 `remote_directory` 非空不能单独证明任务已提交。`tasks::Target::may_have_server_result` 排除本次进程中的 Checking、Ready、Queued，以及明确 Cancelled 的目标；单目标按钮、批次目标与实际请求都检查该边界。请求仍核对原账户、地址、主机信任，不因目录或读取时间字段存在而越过提交状态。

状态不确定时保留只读核验能力：提交前先把所有就绪目标持久化为 Queued，再将执行决定交给 worker；重启读取时 Queued／Submitting 转为 Unknown，不能据此断言没有提交。Unknown、已接收或已结束任务在原目录和身份可用时仍可查询。找不到保存结果保留未知，不自动重放；明确取消的目标不发出查询，也不因缺少服务器记录而改成未知。

`python tools/unsubmitted_queries_smoke.py` 以真实预检查目录和单槽提交队列覆盖取消、已接收与未提交的混合批次、重启、旧状态、不确定结果及中文窄窗口；夹具核对查询和启动次数。


## 独立账户任务的批量停止

`task_stops` 与 `task_stops_ui` 在 Server records 中提供跨页选择、独立认证和审核，不复用普通批次控制器；普通批次运行时仍能使用。一次最多 100 个任务、32 个原 SSH 账户；同一 SSH 端点每批只选择一个账户，其他账户分批审核，避免系统级任务编号冲突。连接信息和主机指纹重新核对，UID／HOME 在 sudo 之前读取；SSH／sudo 凭据只在临时内存中保留，离开页面或关闭审核清除界面侧引用；已发出的一次性检查或已接收任务的有限观察在结束后释放自己的访问。选择可独立清空，不需要单机工作区或 SFTP。

预览只读，要求 Python 3.8+、运行中的 systemd、支持 JSON 的 busctl 及 cgroup v2。固定程序核对原账户的 700 任务根目录、700 记录目录、输出及可选元数据的无链接身份；通过管理器保存的 ExecStart 核对原任务结果写入包装，拒绝只靠同名单位或自填元数据授权。busctl 的原始参数可能包含脚本正文，只在远程核验时使用，不写入预览、任务历史或公共日志。审核保存调用身份、程序摘要、原进程起始计数和 cgroup 身份；无法核验的任务明确拒绝，提交仅包含通过核验的行。

显式提交前先保存本地批次；原账户经固定上传通道暂存源程序和精确请求，root 准备器核对上传所属 UID／摘要，冻结到 `/var/lib/arcnix/task-stops/<编号>`。该固定上传标记与已有三类维护程序共用 4 MiB 输入上限；普通命令与密码输入边界不变。启动前 UI 再持久化原任务目录并确认身份，保存失败或审核已关闭就不发启动请求。明确未提交失败／取消的目标清除查询目录。

systemd 持有有限控制程序。新的 `Access::Control` 有意不获取全局运维锁，否则无法停止持锁的目标；它不归类为只读任务。最多四路 SSH 提交，收到服务器接收后释放提交名额，有限结果观察独立进行；观察结果去重，客户端关闭不承担停止或报告的执行。服务器逐项再次核对原运行实例，在写入 pending 后最多发送一次不阻塞的管理器 stop 请求，不按 PID 强杀，也不自动重试请求。随后观察最多 90 秒，整体由服务器 180 秒限时保护。原 cgroup 的 `cgroup.events` 确认递归无进程，且原进程起始身份已不在，才确认停止；自然退出另行标识。调用身份或源记录变化后拒绝继续控制，未证实的请求保留未知。冻结执行器以私有执行锁和报告阶段拒绝重放。

`record.json` 保存精简的任务数量、选中编号摘要及账户／根目录／编号联合摘要，不放完整私有预览。最终公共日志中的有界 `ARCNIX_TASK_STOP_V1` 报告逐项绑定原编号，客户端同时核对批次编号、程序版本、审核摘要和最终阶段；退出 0 缺少完整证明不会成为已确认成功。最近批次和无本地历史的服务器日志都提供可读结果，列表的退出 0 记录先提示查看停止报告。

停止可能留下部分变更，不承诺业务回滚。systemd 不提供本功能所需的“仅在调用身份等于指定值时停止”的原子条件，本实现是在请求前反复核验；不能据此保证与任意外部 root 写入者完全无竞争。记录被其他操作改变、服务器重启、SIGKILL 或磁盘故障时保留无法确认，不自动续跑。私有控制审计当前保留，不纳入现有清理器自动删除；账户中的停止结果明确识别为受保护核查依据，清理预览不会把它当作普通候选。

验证入口为 `python tools/task_stops_smoke.py`，以及设置 `ARCNIX_TEST_SYSTEMD_DISTRIBUTION` 后运行 `cargo test -p arcnix-core --test task_stops_integration -- --ignored --nocapture`。后者只创建唯一编号的自有有限服务，按精确 Description 核对后停止，要求 cgroup 空／消失后才删除自有临时目录及私有控制记录；不连接线上主机。


## 退出回执与运行实例绑定

新 systemd 任务在运行包装器入口捕获并验证 `$INVOCATION_ID`，在负载返回后将 `ARCNIX_TASK_RESULT_V1\t<task-id>\t<invocation-id>\t<exit>\n` 整体写入 result.tmp，再 rename 为 result。沿用原目录、文件权限、FD 9 操作锁及提交边界，不另写可能与退出值交错的独立绑定文件。该文件最多 192 字节，退出值须为规范的 0–255，运行实例为 32 位小写十六进制。没有有效运行实例时不运行负载，也不伪造回执。

`task_result` 统一解析最近任务和独立账户记录的退出证据；原数字退出值可识别为旧格式，但不能作为本次查询的完成证明。任务编号不同、仍加载的服务运行实例不同、运行实例无法核验、截断／多余字节等保持未知。服务管理器明确报告单元不存在时，完整的原任务回执仍可用；管理器不可用不等于单元不存在。运行／停止状态继续优先，查询前后状态或实例变化时不确认完成。只是查看文件不重启服务、不清除旧结果、不重放任务。

单目标查询沿用 ARCNIX_TASK_QUERY_V2。独立记录新增第 3 版行：R、id、modified、bytes、before-state、before-invocation、after-state、after-invocation、result64、3、metadata64；继续接受第 2 版行读取旧日志，但缺少运行实例不能重新确认退出。两种读取共用有界 service／exit shell 片段；记录列表、详情与最近任务得到一致状态。旧客户端仍发送自身旧读取器，遇到更大的新回执只能显示未确认结果，不会把它解析为数字成功。

新的记录存储／清理预览只接受完整绑定回执，并在仍加载时核对当前运行实例；旧数字结果、缺失或不匹配回执保护其证据。已冻结的旧服务器执行器保持原版本，不因升级重写或自动重试。已保存在本地的历史快照不会被离线重新核验，重新查询服务器才使用本规则。

停止控制器可核验旧数字包装器和新绑定包装器的精确后缀，不放宽为任意 shell 后缀。读取期间同一运行实例的 ActiveState／MainPID 正常变化与真正身份变化分开：审核阶段需要重新核验；已发送一次 stop 的控制任务继续有限读取，仍须证明原进程和 cgroup 为空。不同运行实例立即拒绝，不补发 stop，也不把状态变化当作完成。

回执是服务器保存的执行证据，不是签名、应用健康证明、任意 root／账户写入者的防篡改承诺或通用掉电恢复协议。systemd 运行周期定义见 [systemd.exec 的 INVOCATION_ID](https://www.freedesktop.org/software/systemd/man/256/systemd.exec.html)，失败单元清除及回收行为见 [systemd.unit 的 CollectMode](https://www.freedesktop.org/software/systemd/man/256/systemd.unit.html)。


## 多服务器当前配置对比（历史设计，桌面页面已移除）

配置中心的只读对比与发布、恢复记录分别使用页面状态。`configuration_compare` 定义同一路径、范围绑定的快照和本地差异；独立 worker 最多并发 4 个短连接，批次上限 32 个可信端点，沿用共享搜索／分组和账户去重规则。普通读取不探测 sudo，只有明确勾选管理员选项才请求提权。停止及离开页面使旧代数失效，停止派发后续目标；实际连接可在有限超时内结束，在原池退出前不创建新池。更新安装也等待该池退出。

服务器读取器需要 Linux、Python 3.8+、`timeout` 及 `/proc/self/fd`。固定到 `/` 后启动隔离 Python，单文件最多 128 KiB，服务器 12 秒 alarm／15 秒 timeout 加 2 秒宽限，SSH 流最多 35 秒，stdout 256 KiB、stderr 64 KiB。路径按字面量传递，拒绝伪文件目录。解析符号路径后逐级固定目录，以 O_PATH／O_NOFOLLOW 先证明末项是普通文件，再打开固定描述符读取；检查读取前后身份、大小及纳秒时间和路径指向。允许读取硬链接，拒绝不稳定快照；这是分时读取，不承诺跨机器原子快照，也不声称防止任意特权写入者。

先校验完整原始字节的 SHA-256，再对解码后的正文隐藏本次已知认证信息，原始摘要用于一致性判定。隐藏匹配只遍历原文，不重新匹配标记；去重凭据且限制输出，避免短重复凭据造成递归膨胀。所有文件中的其他秘密仍可能显示，帮助中明确说明。临时快照、正文、差异不写入任务历史或配置；本地 diff 采用 similar，算法限时 120ms，展示最多 32 KiB，完整字节摘要不受预览截断影响。UID／GID／mode 差异单独报告。

同范围刷新失败保留带原时间的旧快照，并禁止它参与对比或填入草稿。完整、非空且未隐藏的基准只可填入空的 Custom 发布草稿，校验／重载／健康命令保持待填写，目标与发布继续走原审核。该显式草稿遵循编辑器自身内存生命周期；离开对比页清除对比数据，不覆盖已有草稿。帮助、来源及长错误使用统一 `?`，可悬停／点击；正文 14px，标签和代码 13px，辅助信息至少 12px。


## 连接期间的资源趋势

`metric_history` 保存本次连接的单调时间点、CPU／内存百分比和排除 lo 的网络合计速率，最多 900 秒及 1,024 次读取。窗口为最后接收的读取之前 1／5／15 分钟，初期只展开已有时长。零是有效观测；缺失、错误、负值及非有限值保留为缺失，不将它们画为零。读取失败、页面边界、暂停／继续及服务器 uptime 回退会分段。一次读取距离前次完成超过两个配置采样间隔时，也先丢弃速率基准并分段，避免把长时间排队或网络延迟连成连续采样。

`MetricState` 随现有连接代数清空，沿用原 SSH 请求和一个 pending 请求的限制，不新增采样工作线程、服务或客户端持久数据。只有当前服务器资源页可自动读取，暂停后只允许明确手动刷新；已有读取可完成。连续手动刷新仍能取得有效计数对，切页、恢复自动采样和长间断后重新建立基准。失败保留原数值与成功接收时间，图中加入缺失点，不刷新为伪造的成功。

Rust 负责数据和范围，`resource_trends` 只将有界 JSON 交给内置 `resource-trends.js`。该脚本生成 SVG、键盘／指针取值和响应式轴，不发请求、不设定时器、不写 localStorage。document-start 时观察 document，等待实际宿主节点；重建及卸载时核对节点并断开 ResizeObserver。SVG 以实际内容宽度绘制，防止 padding 使坐标和字体整体缩小。CPU／内存固定 0–100%，接收／发送共用所选范围刻度，以实线／虚线及标签区分。图例使用当前字节单位，轴采用简短单位；数值按真实时间间距绘制，缺失或分段不插值连线。

使用说明集中到 `?`，范围／状态／数值保留在页面，网络接口计算说明也移到帮助中。Tab 可聚焦图表，左右方向键及 Home／End 取样，Esc 关闭图中提示；不修改全局快捷键。图表由应用自带代码绘制，未加入外部图表运行库或在线资源。当前仅绘制连接期间的 CPU、内存和合计网络趋势，不代表关闭客户端期间的历史监控。


## 配置正文参数与逐服务器候选（历史设计，桌面页面已移除）

`configuration_templates::Source` 仅解析显式启用参数模式的候选正文，支持 `{{name}}` 和四个花括号的字面转义。最多 32 个 ASCII 参数名、每值 4 KiB 单行文本，保留原样、单次替换，不重新解析替换值；完整渲染逐片段检查 128 KiB 上限，拒绝空文件与控制字符值，不先构造无界字符串。目标路径及校验／重载／健康条件不参与替换。普通配置模式完全保留旧的正文处理。

编辑器默认值与运行表单 Session 分开保存；Session 用 Arc 共享只读 Source，保存默认值、覆盖值和展开状态。过滤不改变已选值，统一目标选择 commit 负责移除取消目标的覆盖与展开状态。关闭表单或成功进入预检查后清除 Session，服务器操作使用已冻结候选；取消发布审核回到原草稿，恢复记录审核不打开新草稿。对比基准复制到草稿时关闭参数模式，避免将文件中的原样花括号解释为旧参数。

预检查前为所有选中目标完成本地渲染，再由 Template 冻结每个 Job。各候选沿用同一选项，分别计算实际正文摘要；批次 revision 包含原定义及有序目标记录。worker 在连接前按目标解析对应候选，保留批次 revision 和单目标作用范围；不能将解析后的候选重新指向另一目标。原 SFTP／服务器 Python 预检查、私有原始备份、diff、systemd 执行及健康／回退流程继续使用各自 Job，服务器不需要模板引擎或新服务。

本地 Task 新增可缺省的 configuration_targets，保存 Record／Spec，不保存原文或参数；原 configuration 保留一个公共选项代表，旧记录未提供映射时沿用共享记录。新的 configuration_for 在映射存在时核对完整目标集合、公共选项和合法摘要，再选择精确记录；缺失或损坏不会回退到代表记录。恢复再次核验原服务器和私有来源设置。旧客户端不理解映射，若以代表摘要恢复其他不同候选，既有服务器 Spec 全量比较会拒绝；不会扩展旧服务器执行器的能力。

脚本库／通用参数与配置正文参数分开；此功能不是通用脚本参数扩展，也不是持久配置模板库。编辑器内容按既有内存生命周期保留，已接收任务只依赖服务器上的完整候选和工具，不依赖原运行表单或客户端常驻。


配置编辑内容、默认值、参数模式及非默认的路径／校验／健康设置都视作内存草稿。updates_ui 的统一 idle 检查在草稿存在时同时拒绝手动安装与自动重启倒计时，不只检查当前页面；更新可继续下载和验证。更新页提供短状态、`?` 及返回草稿入口。丢弃使用本地确认，取消保留数据，确认只重置 ConfigurationState，不改历史、服务器版本或已经冻结的任务。此机制不将私有正文自动写入磁盘，也不替代用户主动关闭客户端前处理草稿。


## 服务器环境与标签

ServerProfile 增加可缺省且空值不序列化的 environment／tags，保留配置 schema 1。环境最多 32 个 Unicode 字符／128 字节，最多 16 个标签，每项同样有界；控制字符、首尾空白、标签分隔逗号及大小写无关重复值不能进入配置。编辑器在独立 Labels 页接受逗号／中文逗号分隔的标签，修剪空白、忽略空项并保留首次出现的大小写；环境保存前修剪。ConfigStore 正常完整验证及原子写入仍适用，非法值不覆盖已有文件。它们只是用户填写的本地分类，不检测服务器环境，不授予权限，也不成为健康或执行证据。

服务器树与 target_selection 共享分类搜索辅助函数：多词按 AND 匹配名称、地址、账户、端口、分组名、环境及标签。目标 Filter 新增两个会话字符串，环境／单个标签按完整值及大小写无关匹配，空值表示不限，与分组／搜索／仅已选共同生效。Template::allows_target 仍先约束可见目标，选择及执行前继续核验信任、重复端点与 32 台上限。过滤不清除选择／凭据／逐目标配置参数，统一审核已选会重置所有筛选；有隐藏目标时原执行守卫仍拒绝继续。标签不写进任务请求或执行版本，也不在预检查后重新匹配目标。

共享控件用于脚本／安装／备份的运行表单。备份跨服务器访问端的原搜索也自动包含分类；其他独立记录入口的选择列表未因此新增分类筛选器。控件只有在配置存在分类或筛选非空时显示，说明放进 `?`，目标行展示环境及可展开的完整标签，服务器树只补充短环境标识，避免标签占满侧栏。

服务器编辑器保存打开时的原始 profile。若只改 environment／tags，则把分类合并到保存时的当前 profile，保留期间更新的浏览位置等数据；不向 worker 发送断开，不清理传输队列或重置分栏。其他字段变更沿用原完整保存与断开规则，单机系统操作忙碌时仍保护连接设置。仅改分类可在任务期间保存；新服务器仍经过完整验证。筛选和标签编辑不发 SSH、APT 或 systemd 请求，也不增加后台采集与客户端常驻。

目标分类提示使用可响应更新的原文帮助内容，不将用户标签交给界面翻译目录。连接 Probe 请求改为持有 Box<ServerProfile>，worker 进入分支后解包，避免新增资料字段扩大整个请求枚举；连接参数、主机信任和请求顺序不变。


## Servers 本地记录总览（历史设计，桌面页面已移除）

备份覆盖遍历每个已分配策略，匹配当前版本、仓库及当前执行账户身份，分别保留成功备份、完整性检查、恢复演练和最近尝试。较新失败不抹掉旧成功，也不会被旧成功隐藏。检查与恢复不计作备份；跨执行端演练必须保存明确来源、有效检查范围及当前执行端身份。日期为成功任务开始时间，不推断备份时刻或 RPO。

总览保留已选工作区及终端，隐藏单机操作标签和连接控制；返回同一服务器不重新认证。进入总览即打断资源基线，迟到采样同样留下间隔，回来再按原规则读取。视图共享一次派生的本地汇总，筛选、年龄及刷新只重算本地记录。辅助说明和逐策略详情放入可悬停／点击的 `?`，保留 14px 正文、13px 标签及至少 12px 辅助文字。

## 客户端配置快照与恢复

`configuration_backups` 复用 `ConfigStore` 的 schema 1 文档及完整模型校验。导出冻结审核时的内存配置，SHA-256 对应实际文件字节；不递归读取密钥或其他路径引用。源文件与候选均限制为 4 MiB，包含最终换行；`store::encoded` 同步修正原等号边界，避免保存后超过读取上限。快照是可读 JSON，不提供加密或来源签名。Unix 新文件设为 0600，Windows 继承目标目录 ACL，应选私有目录。

新文件通过自有临时文件、同步及现有 no-replace rename 发布，不覆盖同名文件。恢复先复制候选并以当前加载的信任缓存替换导入信任，再冻结源字节、内存配置及当前磁盘文件。提交分别重新核对三者，逐字节保留原文件后才走普通配置保存；当前文件拒绝链接。原文件保留上限为 16 MiB，以便修复损坏文件及旧版 4 MiB 加换行的边界文件。活动文件不存在时无需创建原文件备份。最终复查不能提供跨编辑器 CAS，恢复时应关闭其他编辑器。

`configuration_backup_ui` 位于 Settings → General，源文件读取、替换审核和实际保存是分开的动作；说明使用 `?`，JSON 预览按需显示，审核时缓存并在 UTF-8 边界截取 64 KiB。修改路径或重新读取／审核清除旧预览，关闭和导航清除私有内容。活动传输、提交、读取或文件操作阻止提交；空闲连接可保留到保存成功后再断开。恢复保留独立任务历史和内存发布草稿，丢弃旧准备目标及会话凭据。`Ui::writable` 使用响应式 Cage，使损坏启动配置恢复后即可重新保存，无需重启；任务历史的可写状态仍独立判断。

验证入口：`cargo test -p arcnix-core --lib --locked configuration_backups` 与 `python tools/configuration_backup_smoke.py`。桌面专项包含真实回环 SSH／SFTP 连接、限速传输中的替换阻止、恢复前后信任及历史／草稿保持、源／当前文件变更、损坏配置恢复和重启。它验证 Windows 当前宿主行为，不代替其他平台的文件系统／权限矩阵。

## 脚本收藏

`AppConfig::script_favorites` 保存 `script_favorites::Favorite { source, script }`，复用官方／个人的 `Source` 身份，缺省为空且空列表不写入 JSON。最多 256 个不同引用，标识沿用脚本的 256 字节及无控制字符限制。读取配置允许旧目录中已不可用的引用，避免应用目录版本变化阻止全部配置加载；只呈现当前实际存在的脚本，新增引用必须指向当前来源的定义。

收藏不复制脚本正文或固定版本。编辑及 bundle 显式替换沿用个人标识，删除同步清理该个人引用；复制或导入副本有新标识，不继承原收藏。脚本分享结构仍只有定义，完整配置快照自然包含收藏。UI 在保存成功后才发布新状态，配置只读时禁用写入，失败就地显示并保留原星标。混合收藏列表的翻译、安装说明和编辑入口按 `Template::source()` 判断，列表 key 包含来源，不能用当前标签页推断官方身份。

验证入口：`cargo test -p arcnix-core --lib --locked script_favorites` 与 `python tools/script_favorites_smoke.py`。后者核对同 ID／名称的来源隔离、编辑／复制／导入／分享、重启、当前定义的双服务器执行及独立结果查询、真实 Windows 文件共享锁造成的保存失败、只读启动配置，以及 SVG、键盘、中文窄窗口和 `?`。
